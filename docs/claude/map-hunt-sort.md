# 地圖巡怪：負重、自動整理、可 ride 的格子

- 負重（`checkLoad`，設定 `loadMaxPercent` 預設 90、0＝不檢查）：`fightRoom` 每打完一隻設 `state.loadFought`，`plan` 開頭看到就 `countLoadRoom`（一間只算一次）：還不知道負重（`state.load` 是 null）、上次負重 ≥ `loadAlwaysPercent`（預設 80，0＝不用）、或打完的間數 `loadRooms` 到了這次抽到的 `loadEvery`（`loadCheckEveryMin`～`loadCheckEveryMax`，預設 3～6，`random()`，`checkLoad` 每次歸零重抽）才設 `state.loadDue`，接著 `checkLoad`；整理回來與只下 fight 的 `assistOverweight` 直接設 `loadDue`，不經間數。`checkLoad` 送 `deps.ask('i', 'inventory')`，`ASK` 表多一個 `inventory`，`Parse.parseLoad` 讀「載重 N%」，讀不到就不檢查；超過就走下面的自動整理，前往與回程指令都沒填就 `finish` 警報（**舊的 `unloadCommand` 欄位與 `unloadTick` 已移除**）。檢查在「整個房間」打完之後（同房間還有怪會先打完）。測試底座的 `REQUIRED` 預設 `loadMaxPercent: 0`、間數 1～1。
- **可 ride 的格子**（規格與票在 `.scratch/hunt-load-ride/`）：打怪的地圖有些格子不能 ride，整理的前往指令與回家指令在那裡送不出去。儲存 `mapHuntRideRooms`＝`{ 區域: ["區域/房間"…] }`（`map-collect.js` 的 `RIDE_KEY`、`normalizeRideRooms`（讀回只留文字、屬於那一區、不重複，空的區域拿掉）、`toggleRideRoom`；設定備份的巡怪區塊）。面板巡怪列的 `.hride`「可 ride」（`content.js` 的 `toggleRideHere`，讀改寫排成 `rideWrite` 一條）把 `currentRoom` 這一格加入或拿掉，讀不到房間時說明；按鈕文字依目前這一格記過沒有寫「可 ride ✓」或「可 ride」（`rideStore` 啟動時讀、`storage.onChanged` 更新），結果在巡怪列前面顯示 `RIDE_NOTE_MS`（4 秒）。地圖視窗：`map-collect.js` 的 `refreshMarkUi` 每次一起讀，`markRideRooms` 把目前顯示區域記過的格子加綠色內框（`box-shadow` inset、`data-catworld-ride`，和選怪的紅底可以在同一格）。引擎的撤退（`map-hunt.js` 的 `retreat(why, token, then, { takeOver })`／`retreatStep`／`failRetreat`，`deps.rideRooms` 讀整份儲存）：這一區（`state.area`）沒記格子或已經站在格子上直接 `then`（行為逐字不變）；否則 `state.retreat`（`{ why, rooms, then }`），`plan` 一開始交給 `retreatStep`：到了格子記一行「撤退」、清掉撤退途中聽到的「想殺死你」（`attacked`、`hostile`）並 `then`，否則找最近一格的路線（學習出口開著時先嚴格圖、沒有才寬鬆圖，而且和 `plan` 一樣：出口沒讀過先 `learnHere`、第一步不在已知出口就 `startTrial`），用一般的 `walk` 走一步（移動逾時、重送、走錯都照一般流程）；`skipTarget` 與連續讀不到房間在撤退中改成 `failRetreat`（紀錄寫「撤退 失敗：原因」，停止並警報，不做 `then`），路過檢查（`wantsPassCheck`）與反擊在撤退中不做，擬人化（打錯字、故意走錯、停頓）不經過這條路；自己回模式氣低於休息線時照常停下來休息（`tick` 的 `restStep`）。面板寫「為了X，走向可 ride 格子 Y…」。讀格子要等，期間 `state.retreatPending`（`{ why, then }`）擋住重複開始；`takeOver`（預設開）決定要不要馬上把階段換成 `plan`。目前套用在：**巡完一輪**（`standbyAfterRound`，重生前停打的 `spawnPause` 也走它但不數掛機休息：人在巡怪地圖上就先 `retreat('standby')`，到了才送待命指令；`sortAfterRound` 開著而且有設定整理（`roundSorting`、`sortConfigured`）就 `retreat('roundSort')`，到了跑 `sortOut(…, { then })`：賣完不送回程、不設 `sorted`／`loadDue`，直接 `then` 送待命指令。等完重生時 `startRound` 看 `awayFromHunt()`（地圖房間不在 `state.area`）：不在就和休息一樣走 `returnFromRest` 送 `restReturnCommand`（紀錄寫「待命 回到巡怪區」），沒填就停止並警報；測試 `round end:`）；負重超標要整理（`checkLoad` 決定 `sortOut` 前，完整與只下 fight 模式都經過；超標設定為停止時不撤退）；掛機休息（`waitTick` 的 `standby`：待命指令照舊原地送、跑完之後撤退，到了才把階段換回 `standby`、設 `rest.homed` 並送回家指令）；沒藥與危險線（`retreatHome(why, reason)`：沒藥＝吃藥、精神、內傷的指令送出後看到沒藥關鍵字，先清掉 `state.eating`；危險線＝自己回模式的戰鬥中 `healInFight`、只下 fight 模式、掃描的 `vitals`，試跑照舊原地回家）：已經在撤退或正在讀格子就把 why／then 改成這次的回家（同一個原因不重記；危險線最優先，之後的沒藥不改它），所以撤退中再到危險線不會另起撤退；在 `HOME_IN_PLACE`（`sort`、`area`、`return`，各有自己的流程）、試跑、掛機休息已經回家（`rest.homed`）、人不在巡怪區地圖上時照舊原地 `goHomeAndStop`；打架中（含只下 fight）先 `deps.dropQueue()` 丟掉巡怪還沒送出的指令，再結束這場（`state.fight` 清掉、`fightOne` 回 `stopped`，不再送打怪指令，巡怪紀錄寫「打完 不打了：…」）再馬上走；一輪結束後等重生（`wait`、`standby`）人還在巡怪區，也馬上走；其他用 `takeOver: false`，不搶正在走的一步或看房間，`plan` 在讀格子期間不往目標走，`fightRoom` 在打下一隻前、`assistTick` 一開始看到 `state.retreat` 或 `state.retreatPending` 就收手回 `plan`。只下 fight 延後送的 fight（反應時間）、反擊入口在撤退或讀格子期間都不動作。危險線撤退途中不休息（`fleeingDanger()`：`vitals` 與 `tick` 走下一步前都不 `restStep`，開始時把 `resting` 清掉）。遊戲在戰鬥中會不會拒絕移動沒有樣本，走不動就照走不到處理）。走不到時停止並警報、不送回家指令；設定頁回家指令與前往整理處的指令欄有一行提醒。測試 `tests/map-hunt.test.js` 的 `ride:` 與 `chain: sorting in the second area walks to the ride room…`、`tests/map-collect.test.js` 的 `ride rooms:`。
- **自動整理（永動機）**（`map-hunt.js` 的 `sortOut`、`runStep`，設定 `tripCommand`／`returnCommand`／`altId`／`sortPerHour`；前往、回程至少填一個才走這條，都沒填就停止並警報）：`checkLoad` 超標時 `sortOut` 是一條 async 流程（每個 await 之後都要確認 `state === token`；`phase` 為 `sort`，`tick` 在這個階段什麼都不做，只有 `vitals` 照常跑）：前往指令（路線與鑑定都寫在裡面，`runStep`：`deps.send` 加 `macroRunning` 等它送完，等太久 `SORT_STEP_TICKS` 算失敗）→ 鑑定指令（`deps.watch` 從前往指令開始就抓輸出，鑑定指令送完再靜止 `SORT_QUIET_MS` 才停，所以好幾個鑑定地點的路線與指令可以全寫在前往指令裡、鑑定指令留空）→ `ask('i')` → `Parse.parseInventory`（`*` 已標記、`ˇ` 穿著中、同 ID 第 N 件 ref 是「ID N」，和怪物 ref 同一套，**穿著與標記的也一起數是推測，沒驗證**）→ `deps.keepers(輸出)`（`content.js`，用 `zap-equipment.js` 的 `pickKeepers`：武器只留 `mainWeapon` 類別開頭相符的、判 better／keep／沒基準的留；回 `{ total, mainWeapon, kept: [{ name, category, why }] }`，巡怪紀錄寫一行「整理 鑑定 N 件，主要武器 X；留下：…」，每個 secure／give 再寫一行送出的指令與遊戲回應的第一行，因為物品常有好幾個 ID、`i` 只顯示第一個，ref 可能對到別件）→ 背包裡名稱對得上而且沒標記、沒穿著的逐件 `secure ref`（有 `altId` 改 `give ref to altId`，回應要有「標記完成」／「你給」，沒有就停止並警報、不賣）→ `sell all`（回應字樣沒有樣本，`ASK.sell` 的 pattern 是猜的，最多等 8 秒）→ 賣完停留（`sortLookMinSec`～`sortLookMaxSec` 秒隨機，預設 20～60，0～0＝不停；`phase` 仍是 `sort`、`sortStage` 為 `look`，停到 20～50% 時用 `ask('i')` 送一次 i，其餘時間不送指令，所以看門狗不會響；寫一行「整理 賣完停留 N 秒」紀錄；測試共用設定 `REQUIRED` 是 0～0，`sort: after selling it stays…` 另外設 40）→ 回程指令 → 等地圖房間在 `state.area` 才繼續（多等 2 倍逾時）→ `state.sorted`＋`loadDue`，下一次 `checkLoad` 還超標就停止（整理只做一次）。**一律給小號的物品**（設定 `giveItems`，頓號或逗號分開的英文 ID，`giveList` 整理：只留符合 `SAFE_ID`、不分大小寫去重、最多 10 個、每個最多 30 字；空＝功能關閉、行為與沒有這個欄位時逐字相同）：`sell all` 之前，對每個 ID 找背包裡沒標記、沒穿著、ID 相同（不分大小寫）的行，數量取名稱開頭的中文數詞（`Parse.quantityOf`：「二株」＝2、「十二個」＝12、沒有或看不懂＝1，使用者貼的樣本「二株不知名藥草(unknown herb)」），有 `altId` 就送「數量總和」次 `give <ID> to <altId>`（遊戲的 give 一次一件，每次都送單純的 ID，使用者確認），回應要有「你給」；沒有 `altId` 就每個符合的行送一次 `secure <ref>`，回應要有「標記完成」；沒成功與好裝備的 give／secure 一樣停止並警報、不賣，每次送出寫一行巡怪紀錄「整理 … 一律給小號」。`keep` 模式沿用已讀的背包（排在好裝備的 secure／give 之後）；`none` 模式本來不送 `i`，只有 `giveItems` 非空才多送一次。`altId` 欄位在 `none` 模式也會在 `giveItems` 非空時顯示。測試 `sort: items to always give…`、`sort: sell-everything mode also gives…`、`sort: without an alt ID the listed items…`、`tests/hunt-parse.test.js` 的 `quantityOf`。設定 `sortKeep` 為 `none`（全賣）時跳過 `i`、`keepers`、`secure`／`give`，前往指令跑完（含靜止 `SORT_QUIET_MS`）直接 `sell all`，只有使用者自己 `secure` 過的不會賣；預設 `keep`。每小時最多 `sortPerHour` 次（`state.sortTimes`，用 `deps.now()`；巡完一輪的整理也算）。**巡完一輪就整理**（`sortAfterRound`，預設 off，在 sort 組，不看 `loopRounds`；開著時 `sorting` 也為真，整理的欄位都顯示，`tripCommand` 變必填，`overloadAction` 只看 `loadMaxPercent`；**沒開 `loopRounds` 時**，`endRound` 在這一輪處理過房間（`state.handled`）而且有設定整理（`sortConfigured`）時走 `sortThenStop`：和下面一樣先 `retreat('roundSort')` 到可 ride 的格子（沒記格子或人不在地圖上就原地），`sortOut(…, { then })` 整理完不回程、不送待命指令，`finish('巡完、整理完，已停止')`，正常結束不警報；什麼都沒處理就不整理、照舊停止；跨區時是整條路線最後一區巡完才整理，掃描不整理）見「可 ride 的格子」的巡完一輪。**不自動 `unsecure all`**（會洗掉使用者手動標記的東西）。`secure`、`give`、`sell all` 的字樣來自使用者貼的真實輸出（標記完成、你給…、你把…賣掉）；`sell all` 是否跳過已標記物品、鑑定指令與區塊名稱和背包名稱是否一致沒有實測。測試在 `tests/map-hunt.test.js` 的 `sort:` 八條（假背包、商店、鑑定輸出）與 `tests/hunt-parse.test.js`（`parseInventory` 用真實樣本）。
- **負重超標時的動作**（`overloadAction`，`sort` 預設／`stop`）：`checkLoad` 在負重達 `loadMaxPercent` 後先看它，`stop` 就 `finish` 並警報、不走 `sortOut`（也不要求填前往與回程指令）；`sort` 與以前完全相同。只下 fight 模式的 `assistOverweight` 也走同一個 `checkLoad`。測試 `sort: when the over-the-limit choice is stop…`。

# 地圖巡怪：跨區巡怪

- **跨區巡怪**（規格與票在 `.scratch/hunt-chain/`；設定 `chain`，預設關，在「輪與重生」組）：路線存在 `chrome.storage.local.mapHuntChain`＝`{ areas: [{ area, sortReturn }], moves: [指令…], back }`（`moves[i]` 從 `areas[i]` 走到 `areas[i+1]`，`back` 從最後一區回到第一區；`normalizeChain` 讀回時丟掉不是文字、空的、重複的區，指令不是文字當空字串，段數照區數補齊，壞到讀不出就是沒有路線；設定備份的巡怪區塊），試跑結果 `mapHuntChainTrial` 在設定備份的不匯出清單。開關開著、路線有兩區以上才作用（`start()` 的 `chain`，否則巡怪逐字和單區相同）：從角色所在的那一區開始（`chain.index`），巡到最後一區再回第一區，之後每輪從第一區開始；角色不在路線的任何一區、或有任何一段換區指令、回到第一區的指令沒填，就不開始並說明；跨區時起點那一區沒勾怪、沒目標房間也照樣開始；從第一區以外開始的第一輪（`chain.partial`，`beginRound` 清掉）什麼都沒處理也回第一區等重生，不 `finish`。`endRound` 在還有下一區時 `nextArea(huntArea)`，最後一區巡完（照常寫每輪摘要、`loopRounds` 關或這一輪沒處理就照舊 `finish`）`nextArea(standbyAfterRound)` 回第一區再待命、校準、等重生；換區是 `changeArea`（`phase` 為 `area`，`tick` 不動作、`vitals` 照常）用共用的 `walkToArea`（沒送出、沒走到都停止並警報，不重送），到了 `enterArea` 讀那一區的地圖（`deps.areaHtml`）與那一區勾的怪（`deps.target(區域)`，`content.js` 的 `target` 沒給區域時用地圖顯示的那一區）換成那一區的目標；「打怪前補掃」開著、那一區有 `mapVisited` 沒有的房間就先 `scanArea`（走街景模式的路徑，`state.resume` 記下補掃前的 `handled`、`visited` 與每輪摘要統計的複本，掃完 `startHuntAfterPrescan` 放回去、只換回這一區的目標，不重設這一輪，所以補掃的房間不算進「到過 N 間」與每輪摘要），回到第一區時（`defer`）補掃留到 `beginRound` 才做（`chain.pendingScan`，等重生期間不掃；`humanizeRound` 在補掃之前先決定這一輪的設定）；`mapVisited` 一直沒有的房間（讀不到房間不記）每次到那一區都會再補掃；沒有目標房間（補掃沒開、或補掃完仍沒有）就記「略過區」，`plan` 找不到目標直接走下一段；`handled` 與每輪摘要的統計不因換區重設（一輪是整條路線）。面板巡怪列在怪名後面加「（第 N／M 區）」；沒在巡時，開關開著才在巡怪列後面接 `chainStatus` 的跨區狀態（有兩區以上寫整條路線，不到兩區寫「還沒設定路線」；開關關著不寫；`content.js` 的 `refreshHuntChainNote` 在面板重畫時最多每 2 秒重讀一次）；換區中寫「換區，走向 X…」；巡怪紀錄的「換區」寫從哪區到哪區、花幾秒，或「沒有成功：原因」（`walkToArea` 的 `texts.failed`，寫在停止那一行之前；按停止中斷的不寫）。測試 `tests/map-hunt.test.js` 的 `chain:`（`chainWorld`：t、u 兩區，`go-u`／`go-t` 換區並切換顯示哪一區）。和其他功能：重生前停打（`spawnPause`）在第一區以外就 `nextArea(…, { home: true })` 送回到第一區的指令（`back`，玩家照「從最後一區回第一區」寫的，三區以上時在中間區停打可能走不到而停止並警報），在第一區待命、等那個重生；自動整理的回程指令先用這一區的 `sortReturn`，沒填用 `returnCommand`（`sortReturn(settings)`，有填這一區的也算有設定整理），回來後確認在 `state.area`（當下在巡的那一區）；掛機休息的 `countRoundForRest` 只在 `standbyAfterRound`（整條路線巡完、回到第一區）數；擬人化的目標順序、等長路線、停頓只在一區之內（`enterArea` 每區重排 `planOrder`，紀錄寫「擬人化 本區：目標順序」），區的順序照清單；每輪摘要的路線在跨區時房間前面留區域代號（`summaryLines` 的 `keepArea`）。設定頁巡怪底下的摺疊「跨區路線」（`fold-hunt-chain`、`#huntChain`）是 `map-hunt-chain-ui.js`（**只在 popup.html 載入**，popup.html 也因此載入 `map-hunt-ui.js` 取 `PICKS_KEY`、`pickedFor`、`mobsOfArea`）：畫成路線圖（`.hchain-route`，兩區以上加 `loop`：左邊一條虛線從底下的「回到第一區」繞回第一張卡片，樣式在 `popup.html` 的 `#huntChain`；摺疊標題由 `showSummary` 寫成「跨區路線：A → B → ↺ A」，收起來也看得到）：由上往下每一區一張卡片（區名（代號）、勾怪是膠囊形的勾選、那一區蒐集到的怪直接勾，寫進面板「選怪」那一份 `mapHuntPicks`（`savePicks` 讀最新的勾選再只換這一區，不蓋掉遊戲頁剛存的別區；勾著但這一區已經沒有紀錄的怪也列出來，才取消得掉）、選填這一區的整理回程指令 `.hsort`、上移下移刪除），卡片之間的箭頭是換區指令 `.hmove`，最後一個繞回第一區的是 `.hback`；新增的下拉只列有蒐集紀錄的區（`withBuiltin` 後的 `rows`）、已在路線裡的不列；增刪移動都經 `rearrangeChain`（`map-hunt.js`，換區指令跟著「從哪區到哪區」那一對走，原本沒有的一對是空的）；沒填的換區與回到第一區指令欄標 `hmissing`（和巡怪欄位的必填同一種琥珀色），勾了怪但勾的怪在這一區都沒有房間紀錄的卡片顯示 `.hcard-warn`（`msg-warn`）；改了馬上存，文字欄存檔不重畫（`change` 在離開欄位時才觸發，重畫會吃掉緊接著的點擊），增刪移動才重畫，改動一律從最新的路線算起；`storage.onChanged`（路線、勾選、蒐集資料）重讀重畫，正在打字時延到離開輸入框才畫。測試 `tests/map-hunt-settings-ui.test.js` 的 `chain editor:`。**試跑**：設定頁「跨區路線」的 `#huntChainTrial` 送 `HUNT_CHAIN_TRIAL` 給遊戲分頁（`content.js`，巡怪或試跑進行中、驗證碼或真人驗證開著時回 `ok:false`；開始了就回，不等走完；設定頁的按鈕在開始後維持停用，等 `refreshLive`），引擎的 `trialRun`（狀態用和 `start` 共用的 `freshState`，`trialRun: true`、`phase: 'area'`，所以 `on()` 為真：面板的停止、驗證碼、停止一切都會停它，開始鈕停用）：角色要在第一區，`runTrial` 從第一區逐段用 `walkToArea` 送換區指令，最後送回到第一區的指令；只走不打（不送 `l`、不打怪），`vitals` 照常補氣、氣低於危險線回家停止（自己回模式在 `phase` 為 `area` 時不送休息指令，換區與試跑都是：休息指令會打斷換區的巨集）。每段結果 `{ command, from, to, ok, ms }` 或 `{ command, from, to, ok: false, why, where }`（`where` 是失敗當時的房間；走到一半被警報停下，例如危險線回家，也記成這一段失敗，按停止中斷的不記）照段的順序（第 i 段是 `moves[i]`，最後一段是回到第一區）存進 `mapHuntChainTrial`（`deps.saveTrial`），第一個失敗就停、之後的段與被停止中斷的段是 `null`。編輯器在每個箭頭下顯示 `.htrial-result`：成功不上色、失敗 `msg-error`、沒試跑 `msg-warn`，結果的指令或前後兩區和現在的不同就算沒試跑（不必在改指令時刪結果）；試跑結果不擋開始。按鈕在 `refreshLive` 看到 `hunt.on` 時停用（和驗證按鈕同一行）。測試 `tests/map-hunt.test.js` 的 `chain trial:`、`tests/map-hunt-settings-ui.test.js` 的

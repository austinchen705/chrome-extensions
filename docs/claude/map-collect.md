# 地圖怪物蒐集

- `map-collect.js`（manifest 與 popup 備援注入都要載入，要在 `zap-mobs.js` 之後，用它的 `parseMobLines`、`textFromAdded`）監聽 `#content` 新增的文字，進房間時遊戲印的怪物行（`※名稱(ID)`）記給「目前的房間」：地圖視窗 `#map_wrapper` 沒有「你在這裡」的樣式（`emap` 的輸出與地圖房間的 `title` 都沒有怪物資訊，`title` 通常是空的），但遊戲會把所在房間捲到 `#map_anchor`（和一格同大的空方塊）的位置，所以蓋住 anchor 中心點的那個顯示中（沒有 `.invisible`）的 `<a id="m-區域-房間代號">` 就是目前的房間（`currentRoom`）。怪物行出現後等 `SETTLE_MS` 才判斷房間（地圖捲動與印文字不是同一瞬間；這段時間內又走到別間會記錯房間，已知限制）。合併進 `chrome.storage.local.mapMonsters`（鍵 `區域代號/房間代號`，`{ area, room, areaName, mobs, seen }`，`mobs` 是 `名稱(ID)` 字串）：取聯集、只增不減，區域名稱讀地圖標題。收集與設定頁的顯示、複製只認帶括號的 `名稱(ID)`（`isMob`、`rows`；1.58.0 讀地圖 `title` 記下的是房間裡的玩家、只有英文 ID，要濾掉；popup.html 因此要載入 `map-collect.js`）。連不上儲存（孤兒程式）就停止監聽。怪物提示（`zap-panel.js` 的 `showHints`）用 `whereIs` 在怪名下多一行「蒐集到：區域 房間…」（擴充功能的面板與浮層不畫地圖，位置視覺化只做在遊戲的地圖視窗上）。地圖視窗標題列（`#map_header`，遊戲的拖曳把手）右側有 `map-collect.js` 放的下拉選單 `#catworld-mark-select`：列出目前顯示區域（`#map_wrapper` 底下沒有 `.invisible` 的 `div#m-區域`）蒐集到的怪，選一隻就由 `markRooms` 把 `m-區域-房間` 加 inline 紅底（`!important`，比遊戲樣式表優先）與 `data-catworld-mark`，同時只標一隻；選單絕對定位靠右、寬度由 `fitSelect` 依區域名稱右邊剩下的空間算（標題是置中的；不能靠加寬地圖視窗解決，`#map_anchor` 是以 400 寬視窗置中寫死的位置）、事件不傳給遊戲，每 `MARK_TICK_MS` 重讀儲存並重標（換區域與遊戲重畫地圖都靠這個），這個區域沒有蒐集到的怪就藏起來，與怪物查詢開關無關；以上只顯示，不碰路線與分級；`zap-panel.js` 要讀 `mapMonsters` 並聽 `storage.onChanged`，popup 備援注入與 manifest 的 `map-collect.js` 都要排在 `zap-panel.js` 之前）。設定頁「地圖怪物蒐集」只顯示筆數、複製 Tab 分隔文字、清除；不含強度與路線，併進共用表的格式還沒定。jsdom 算不出排版，測試用假的 `getBoundingClientRect` 擺房間與 anchor，真實頁面的置中行為只能手動驗證。測試在 `tests/integration/game/map-collect.test.js`。

- 書生出沒紀錄（六脈神劍助手的一部分）：`content.js` 的 `watchScholar` 在全域觀察器裡看新文字（不管巡怪、掃描、巨集，不送指令），用 `scholar.js` 的 `classifyLine` 認出書生的房間行（`※落魄書生(dire scholar)`）、「誰能給我…呢？」、消失，等 600 毫秒（地圖捲動比印文字晚）再用 `currentRoom` 讀房間、依序用 `addSighting`／`endSighting` 併進 `chrome.storage.local.scholarSightings`（舊的在前，最多 200 筆；一筆＝`{ at, sinceSpawnSec, area, areaName, room, said, matched, result, ended }`，`matched`、`result` 留給判讀與結果；距重生秒數在看到那行當下用 `readUptimePhase` 讀，讀不到是 null）。同一次相遇＝上一筆還沒 `ended`、也沒過下一個重生，後續的行併進同一筆（說的話附進 `said`，和上一句相同的不重複）。設定頁「地圖怪物蒐集」下方列出（最近的在上）並可清除；鍵在設定備份的「累積資料」。測試：`tests/unit/scholar.test.js`、`tests/integration/game/scholar-sightings.test.js`、`tests/integration/settings/scholar-sightings-ui.test.js`。

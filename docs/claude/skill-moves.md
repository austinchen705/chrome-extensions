# 招式列表

- `skill-moves.js`（manifest 與 popup 備援注入的 `files` 都要載入，在 `content.js` 之前；也在 background 的 `importScripts`）：純函式 `parseLearned`（只讀「你所領悟的招式數目為」之後的「名稱 : N 招」，不靠行首，所以輸出沒有換行也讀得到）、`lookup(data, names)`（background 用，只回被問到的武功）、`describe`、`moveText`；加上遊戲頁的觀察器：標題出現後 `ARM_MS` 內的新文字都接上去（輸出可能分批），靜止 `SETTLE_MS` 後解析，向 background 送 `SKILL_MOVES`（`{ names }`）拿資料，在最後一個新增節點後面插一塊 `data-catworld-skills`（自己插入的節點要從觀察器排除）。偵測到標題時一定印一行 `[catworld] 招式列表：偵測到…` 到 console（沒勾開關時會寫明），方便分辨是沒偵測到還是沒開。查詢失敗要把原因顯示在方塊裡。
- 開關是 `chrome.storage.local.zapFeatures.skills`（缺值＝關閉，設定頁 `featureSkills`，和其他輔助功能同一個 `FEATURE_BOXES`），flush 時才讀。`skills-data.js`（約 170 KB）只在 background 載入、不隨每個遊戲分頁載入。已悟 N 招＝資料裡 `moves` 的前 N 招（和 `skills.js` 的「30 × 已悟招數」門檻解讀一致），下一招的門檻取 `levels[N]`。傷害分級的顏色在 `TIERS`（每級 `color` 與 `second` 兩個色系，招式名用 `nameChunks` 兩個字一段、兩色輪流，數字部分用 `color`），傷害類型欄混著說明時只留第一句。`MOVE_NAME_COLORS` 指定逐字配色的招式（鍵＝招式名、值＝每個字的顏色，`describe` 帶 `chars`，`moveRow` 逐字上色、不夠的字退回輪流色）：目前只有打蛇隨棍，色碼抄遊戲 ansi.css 的 XTerm 主題（H5／H2／H1／N7）。
- **招式動畫**（`move-fx.js`，manifest 與 popup 備援注入都要載入，在 `skill-moves.js` 之前）：`lookup` 多帶每招的原文 `action`，`describe` 傳下去；有原文的招式行可以點（`data-catworld-move`，`mousedown`／`click` 都擋住不傳給遊戲），`showMove` 在那一行後面放一個 `CatworldMoveFx.mount` 的播放器（同一頁一次一個，再點同一招重播）。動畫照原文拼出來，不是每招各畫一個：`plan(move)` 的出招動作是原文裡最早出現的 `STRIKES` 動作字，都沒有就照武功的兵器類別（`WEAPON_STRIKE`；`lookup` 帶 `weapon`＝skills-data 的 `type`，`describe` 傳到每一招），意象是招式名＋原文裡依出現先後最多 `MAX_LAYERS`（4）個 `MOTIFS`，顏色、角度、粒子位置由招式名的雜湊決定（同一招每次都一樣）；人物是「你」「敵」兩個字，全用 canvas 畫、不用圖檔；`DURATION_MS`（3 秒，每招再乘 0.9～1.15）內畫完並逐字打出原文（『招式名』換成名字、最後接傷害）。點了才播，所以不看 `prefers-reduced-motion`（使用者的電腦關了系統動畫效果時舊版看起來不會動）；拿不到 canvas（jsdom）時只打字。雪山劍法 11 招的試作頁使用者看過、說可以；真實遊戲頁裡的大小與動畫只在 jsdom 驗過結構。
- 測試：`tests/integration/game/skill-moves.test.js`（純函式用真實資料；遊戲頁用整個 content script 在 jsdom 裡跑、假 background 用 `lookup` 回真實資料；`clicking a move plays…`、`every move in the data gets an animation built from its text…`）。**真實的 careers 輸出文字（節點與換行的切法）只用使用者貼的樣本驗證**。

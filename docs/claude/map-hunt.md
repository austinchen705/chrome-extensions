# 地圖巡怪

- 規格與票在 `.scratch/map-hunt/`（不進 git）：`spec.md`、`issues/01～08`；已完成 01（路線）、02（輸出解析）、03（骨架與走路）、04（看房間、略過有別人的房間、NPC 學習）、05（打怪）、06（補氣）、07（自動學習出口）、08（輪與輪之間）。這和 `.scratch/auto-hunt/`（依重生時間、從醉仙樓出發）是**不同的功能**。
- `map-route.js`（不碰 DOM）：`parseArea(html)` 把地圖視窗裡一個區域（`m-區域`）的 innerHTML 還原成房間與方向指令（一字元一格，`─│╲╱` 雙向、`→←↑↓↘↖↙↗` 單向、中間隔很多連線字元仍算一步、`class="N6"` 的 `<a>` 是通往別區的標記不是房間），`route(graph, from, to)` 用 BFS 回指令陣列（不可達回 null）。房間鍵是 `區域/房間`，和 `map-collect.js` 一致；樣本在 `tests/fixtures/map/`。
- `hunt-parse.js`（不碰 DOM）：`parseLook`（出口轉成指令、`※` 怪物行一行一筆並保留 `<狀態>`、「別人」＝沒有 `※`、有 `(英文ID)`、不是屍體，而且帶 `<狀態>`，或名字前面有稱號（「」括起來、或稱號與名字之間有空白）——沒在發呆的玩家沒有 `<狀態>`，只靠稱號分辨（樣本 `look-player-no-state.txt`，名字已換成假的）；單純的 `物品名(id)` 沒有稱號所以不算）、`parseFinger`（`(player)`／找不到／unknown，unknown 一律當玩家）、`parseTime`（台北時間視為 UTC+8）。輸出文字要有換行才讀得出怪物與別人（遊戲輸出若被拆成節點直接相接，呼叫端要先處理），`content.js` 的 `askGame` 收的是 `#content` 新增節點的文字，節點文字本身要有換行（和 `map-collect.js` 讀怪物行的前提相同）。
- `map-hunt.js`：`create(deps)` 的引擎不碰 DOM 與 `chrome.*`，讀房間、送指令、讀儲存都由 `content.js` 注入；`FIELDS` 決定設定頁欄位、預設值與檢查（`normalizeSettings`，設定存在 `chrome.storage.local.mapHuntSettings`，設定頁用同一份表產生欄位）。`start()` 固定「面板「選怪」勾選的怪（可多隻）＋目前顯示的區域」，目標＝每隻被勾的怪的 `CatworldMapCollect.locate` 在該區域的房間聯集、且在地圖上的；每個 tick（200ms）檢查目前房間（`CatworldMapCollect.currentRoom`）：沒走成就重送一次、再沒走成略過該目標、連續 3 次略過停止並警報；**逾時用 tick 數算，不用 `Date.now()`**（測試底座只縮小計時器、不縮小時鐘）。到的房間要等於路線上的下一間才算成功，走到別間就重算，同一個目標走錯 3 次略過（`wrong` 只在略過時歸零，不然兩間之間來回會永遠不停）；連續讀不到房間要超過逾時才停（`blind`）；`start()` 有 await，`starting` 期間 `on()` 為真（開始鈕停用、再按開始被擋、按停止會取消這次開始，`finally` 之後要再通知面板重畫，否則開始鈕要等下一秒才恢復）；略過的房間（不在地圖上、走不到、走錯）顯示在面板與停止訊息裡。
- 到達目標房間後（`map-hunt.js` 的 `arrive`／`inspect`／`lookRoom`）：**走進來的目標房間先用抵達時遊戲印的房間描述判斷、不多送 `l`**（`state.walkedTo`＝剛走進來的那間，`onText` 從送出移動指令到看完房間為止（`move`／`pass`／`look` 階段）把輸出接進 `state.moveText`，`lookRoom` 用 `parseLook` 讀；要有出口行、而且出口行之後 `ARRIVAL_QUIET_TICKS`（3）個 tick 沒有新輸出才算印完（出口行在怪物行前面，描述可能分好幾個封包，拿半份描述判斷會把有怪的房間看成沒怪，還會讓自動修正位置誤記「沒看到」；安靜時間不比 `l` 的 400 ms 短），連出口行都還沒有時只等 `PASS_WAIT_TICKS`（遊戲沒印描述就不拖慢），有出口行之後最多等到 `ARRIVAL_WAIT_TICKS`（上限與安靜都用 tick 數算，睡眠與 tick 的計時器各自漂移，混著算測試會偶發失敗），印不完、沒有出口行、一開始就站在這間（沒走進來；`walkedTo` 在送出移動指令、開始新一輪、試出口與走回來時清掉，免得讀到舊房間的描述）、或掃描（每間都要確認）才退回送 `l`；巡怪紀錄的「看房間」後面寫「來源 抵達描述」或「來源 l」；路過的房間發現有怪而加進目標後也沿用那份描述，不再多送 `l`），退回時才送 `l`（`deps.ask(command, 'look')`，`content.js` 的 `askGame` 收 `#content` 新增的文字，出現 `ASK_PATTERN` 之後再安靜一小段才交出去；一直等不到 8 秒後交出目前收到的）→ `parseLook`（輸出可能含抵達時印的與 `l` 印的兩份描述，只算最後一份）→ 沒讀到出口算「讀不到房間」（當成走不過去，算進連續略過）→ 不在白名單（設定頁 `npcWhitelist`）與已學到 NPC（`chrome.storage.local.mapHuntNpcs`，名稱陣列，只由 `learnHuntNpc` 寫、設定頁只顯示與清除）裡的 ID 逐一送 `finger <ID>`：`(player)` 或沒回應、讀不懂都當玩家、略過這間且不記；找不到才記成 NPC。有別人的房間算「處理過」但寫在略過清單裡（原因「有別人 ID」），不算移動失敗；所有目標處理完＝一輪結束（見「輪與輪之間」；不等重生時停止並寫「這一輪巡完了」）。`l`／`finger` 的指令走共用送出佇列（來源 `hunt`）；**回應要等指令真的送出之後才開始收**（佇列項目的 `onSent` 回呼，之前印的——例如走進房間時印的抵達描述——不算這個指令的回應，不然 `l` 還在排隊時就會拿抵達描述當答案、漏掉後到的人物行）；房間裡沒有勾選的怪就不問人直接換下一間；ID 要符合 `SAFE_ID`（英數、空白、底線、點、單引號、連字號）才會放進 `finger` 指令，其他當玩家、不送也不學；白名單與已學到的 NPC 都用小寫比對；`inspect` 每個 `await` 之後都要確認這一次巡怪還在（`state !== token`），停止或重新開始後舊的檢查不能再動狀態或送指令。
- **順位數到屍體**（`hunt-parse.js` 的 `slot`、`corpses`；`map-hunt.js` 的 `NOT_ALIVE`、`state.slotCmds`、`aim`）：`parseLook` 另外算 `slot`（房間裡所有東西——屍體、物品、人、怪——一起數的第幾個，`OBJECT_LINE`）與屍體數 `corpses`。遊戲回「看清楚一點，X的屍體並不是活物」（使用者貼的真實輸出：屍體排在怪前面，`f 1`、`k 1` 都打到屍體）時，`onText` 把最後一個帶順位送出的指令（`state.lastAim`）加進 `state.slotCmds`，這次巡怪之後這個指令改用 `slot`；還沒開打的那一場當成 `missing`（重看房間再打）。別名寫成 `fight NPC $1` 的不會遇到這句，照舊只數怪；只靠這句切換，不猜別名的寫法。補刀沒打到（`missing`／`wrong`）不算倒下、不撿屍，重看房間由下一圈補刀；`lookCheck` 補刀時找還昏迷著的同一種怪重送，一直沒打到回 `missing`（`mine` 除了勾選的怪也含這場正在打的那一隻，所以沒勾選但主動攻擊你的怪補刀沒打到也會重送）。**撿屍對帳**：`fightRoom` 記這間送出、沒被拒的撿屍次數，每圈把「房間屍體數 − 進來時的屍體數」比撿過的多的部分補上（倒下時不一定在打它）；`LOOT_REFUSED`（「你還在戰鬥中！只能一次拿一樣」，NFKC 後是半形「!」）被拒的次數還回去，等沒有 `<戰鬥中>` 再送；離開這間前 `lootSettled` 等撿屍送完，好幾隻打你的房間（`hostile > 1`）再等 `LOOT_REPLY_TICKS` 看有沒有被拒，被拒就重看房間（最多 `MAX_STUCK` 次）。測試 `tests/integration/game/map-hunt-fight.test.js` 的 `corpse:`、`tests/unit/hunt-parse.test.js` 的 `slot`。
- 打怪（**指定怪一律用順位，不用 ID**：`hunt-parse.js` 的 `parseLook` 替每隻怪算出 `position`（這份 `l` 或抵達描述裡第幾個 `※` 怪物行，從 1 起算，沒勾選的、昏迷的都算），`map-hunt.js` 的 `targetOf` 送「指令 順位」（`fight 3`，`help fight`／`help kill` 都寫了「攻擊 look 指令顯示第 n 順位的對象」）；`fightOne`、拒戰改 `kill`、補刀、`lookCheck` 重送、只下 fight 模式都用它。不用 ID 的原因（使用者實測）：遊戲的別名 `$1` 只帶第一個字，`f soldier 2` 變成 `fight soldier` 打到第一隻、`f soldier 5` 又打到同一隻（「已經無法戰鬥了」），ID 有空格的怪也一樣；順位只有一個字，別名照樣帶得進去。`parseLook` 仍算 `ref`（ID，同 ID 第 N 個是「ID N」），只是不再拿來送指令；`lookCheck` 重送用這次 `l` 看到的位置，前面的怪倒下後序號會變；`fightRoom`／`fightOne`／`onText`／`fightTick`／`lookCheck`／`healInFight`；結束的字裡 `knockoutKeywords` 代表昏迷：`fight.knockedOut` 為真時 `fightOne` 回 `knockedOut`，`finishKnockedOut` 開著就再 `fightOne(…, { finishing: true })` 補一個 `kill`——補刀只認死亡的字（結束字扣掉昏迷的）、不送特攻，結束後才送 `afterKillCommand`；**補刀時怪醒過來**（`WAKE_UP`，使用者貼的真實輸出「X慢慢睜開眼睛，清醒了過來」「X一見到你，愣了一愣」，同一行要有這隻怪的短名稱）就改成一般的打（結束字含昏迷的字、特攻照 `specialIntervalSec` 從醒來算起），之後又被打昏 `fightOne` 回 `knockedOut`、`fightRoom` 再補刀；沒看到醒來就又被打昏（昏迷字）會馬上再送一次打死用的指令，每次補刀最多 `MAX_STUCK` 次，不等逾時；`lookCheck` 看到那隻怪是 `<昏迷不醒>` 也算昏迷（`lookCheck` 的 `mine` 除了勾選的怪也含這場正在打的那一隻，沒勾選但主動攻擊你的怪補刀沒打到時才會重送））：房間裡有任何一隻被勾的怪就一隻一隻打：`fight <ID>`（ID 要符合 `SAFE_ID`）→ `deps.watch` 餵進來的遊戲輸出裡出現拒戰句就改 `kill`、出現結束句（`endKeywords`）**而且同一行有這隻怪的短名稱**就算這隻打完（`endWordFor`、`shortName`：名稱最後一個空白或「」」之後的那一段，`千夫長 蒙古兵`→`蒙古兵`；遊戲的戰鬥訊息只寫短名稱，例如「蒙古兵死了。」。只看字的話，同房間別的怪或別人的戰鬥印出「某某死了」會被當成這隻死了而去打下一隻、或最後一隻時直接離開，使用者實際遇到；只下 fight 模式的 `assist.dead` 也用同一條，目標記在 `assist.target`；同名的怪分不出來，是遊戲訊息本身的限制） → 送 `afterKillCommand` → **房間裡還有下一隻勾選、非昏迷的怪要打才 `l` 重數**（位置會變），剛打倒的是最後一隻就不重數、記一行「打完這間 最後一隻，不重數」直接換下一間——離開前先等撿屍指令真的送出（巨集就等它跑完，最多 `CORPSE_WAIT_TICKS` 5 秒），因為這一輪剛好結束時 `finish` 會丟掉巡怪還沒送出的指令；重數時連續 `MAX_STUCK` 次數量沒減少略過（原因「打不動」；只有一隻時不重數，所以打不死的單隻怪不會被判打不動，下一輪再來）。逾時（`fightTimeoutSec`）沒結束句就 `lookCheck`：`<戰鬥中>` 繼續等、昏迷或不見了當結束、在但沒在打就重送 `fight`（最多 3 次）。特攻（`specialCommand`）只在怪還活著、距開打或上次已過 `specialIntervalSec`

# 劇本對話

- 規格與票在 `.scratch/scripted-chat/`（不進 git）。兩個遊戲帳號（可在不同電腦）用 `tell` 照一份事先寫好的劇本一人一輪地聊（約 7～8 輪）。擴充功能沒有 LLM、不抓新聞，劇本離線寫好放在共用試算表第三個分頁（來源 `chat`），加上內建備援。**兩台電腦之間沒有任何旁路，只靠遊戲裡傳來的 tell 內容同步**，B 看到的來訊就是唯一的觸發。這是會自動在遊戲裡講話的功能，所以只做手動開場（A 按「現在開一場」），沒有排程。
- 模組分工：`chat-script.js`（純函式，不碰 DOM 與 `chrome.*`；manifest 與 popup 備援注入都要載入，在 `chat-reply.js` 之後、`content.js` 之前，用 `CatworldChatReply.similarity`；隨機數、時間、相似度函式都可注入）、`chat-script-data.js`（內建備援劇本 `builtin-1`～`builtin-3`，手寫、**只在 background 載入**，不含時事、數字、`{對方}`，不綁週末或深夜）、`shared-data.js` 的 `buildChatScripts`／`pickChatScripts`／`sheetEnabled`（試算表解析，content script 不載入）、`content.js` 的接線（`hearScript`、`startScript`、`sayTurn`、`cancelScript`）。
- 劇本格式 `[{ who: 'A' | 'B', text }]`：連續同一個人的句子算同一輪（`toTurns`）；台詞裡用全形 `／` 分開的是同一輪連續送的幾則（`splitParts`）；`{對方}` 送出時換成設定的對方角色名（沒填換成 ID），比對對方的來訊時換成自己的角色名（遊戲頁標題「角色名 - …」，所以設定頁提醒對方要填對）。**驗證規則有兩份，試算表那份要至少和模組那份一樣嚴**（`tests/unit/shared-data.test.js` 對照）：`chat-script.js` 的 `safeText`／`usableScripts` 與 `shared-data.js` 的 `chatLineProblem`／`chatScriptProblem`。規則：台詞不空、沒有 `;`／`；`／`@等待`／換行、每則最多 `CHAT_MAX_PART`（60）字、一份最多 `CHAT_MAX_LINES`（30）句、A 與 B 都有、第一句是 A、「順序」照試算表的列從 1 連續遞增、「週」嚴格是 `YYYY-MM-DD`。**整份劇本只要有一處不合就整份丟掉**（`report.dropped`，帶第幾列與原因）；空的劇本ID 那一列單獨丟。
- 「週」是適用那週的週一日期，從該日起 `CHAT_WEEK_DAYS`（14）天內（含起日、不含終日、本機日曆）才採用，空白＝永遠可用；還沒到或已過期的**不算出錯**，列在 `report.unmatched`。結果的 `until`（窗口終點，毫秒，沒有週就 null）讓 `pickChatScripts(shared, builtin, now)` 在回答的當下再濾一次（共用層快取一小時，過期的不能繼續被用）：共用的排前面、內建補在後面，同一個 id 共用的蓋掉內建的，輸出只有 `{ id, lines }`。
- 設定：`chrome.storage.local.chatScript`＝`{ enabled, role, partner, partnerName, perDay, typoRate, autoEveryMin }`（`normalizeSettings`：預設關、角色 B、`perDay` 預設 3 且是 0～`PER_DAY_MAX`（99）的整數、0＝不開也不接、`typoRate` 預設 3（%，0～100）；`partner` 要符合 `ID_PATTERN` 否則當沒填，`partnerName` 最多 20 字且要是安全文字；留白或不是數字退回預設）。設定頁 `sec-script` 的欄位 `scriptOn`／`scriptRole`／`scriptPartner`／`scriptPartnerName`／`scriptPerDay`／`scriptTypoRate` 每次 `change` 交給 `normalizeSettings` 存回並把正規化後的值寫回欄位；劇本連結 `sharedChatUrl`（結果 `sharedChatResult`、逐列 `sharedChatDetail`、按鈕 `sharedChatRefresh`，`SHARED_FIELDS.chat`）在同一個區塊；打字速度、拆則間隔等細節寫死在 `chat-script.js` 開頭的常數，不開放設定。
- 共用來源 `chat`：`background.js` 的 `SHARED_SHEETS.chat`（`zap: false`＝不載入怪物與解謎資料，劇本不會被它們載入失敗牽連；`enabled`＝`chatScript.enabled === true`，功能沒開就不抓、也不動快取；預設連結在 `DEFAULT_SOURCES.chat`（見 `docs/claude/shared-data.md` 的預設連結），`sharedSources` 的 `chat` 存成空字串就是只用內建劇本；功能沒開不會抓，所以預設連結不會讓沒開功能的人連 Google）。content script 不載入共用資料與劇本資料，改用 `CHAT_SCRIPTS` 訊息向 background 要「目前可用的劇本」（`sharedLayer('chat')` 加 `pickChatScripts`），在頁面快取 `SCRIPT_CACHE_MS`（5 分鐘），功能開著時啟動就預載；回覆的 `ok` 不是 `true`（背景沒答好）就沿用手上的快取、**不更新時間**，下一句來訊再問，不能把「沒拿到」記成「沒有劇本」；連不上 background（孤兒程式）就不開場、不接話。
- A 端：設定頁「現在開一場」送 `START_CHAT_SCRIPT`（**只接受擴充功能自己的頁面**，看 `sender.id` 與 `sender.url`；設定頁是開成分頁的，不能看 `sender.tab`）；`startBlock` 擋掉：功能沒開、角色不是 A、沒填對方 ID、已有一場在進行、今天場數用完，回 `{ ok: false, error }`，設定頁顯示紅字。通過就用 `pickScript` 挑一份（避開最近用過的 `RECENT_LIMIT`＝5 份，劇本不足就挑最久以前用過的）、`recordStart` 記一場、送第一輪。
- **自動開場**（`autoEveryMin`＝平均每幾分鐘一場，0～`AUTO_EVERY_MAX`（1440）的整數，預設 0＝不啟用，留白或不是數字退回 0；只是 `chatScript` 設定物件的一個欄位，不是新的儲存鍵）：`content.js` 的 `scriptAutoWanted`（功能開、角色 A、有對方 ID、`autoEveryMin` > 0、「練功」組 `on`）為真時 `syncScriptAuto` 排 `AUTO_WARMUP_MS`（5 分鐘）的暖機計時器，之後每 `AUTO_ROLL_MS`（1 分鐘）`rollScriptAuto` 擲一次：`Math.random() < autoChance(autoEveryMin)`（1÷N）才算抽中；抽中後要距離 `scriptState.lastAt` 至少 `AUTO_MIN_GAP_MS`（20 分鐘）、不在 `idlePaused`、沒有 `captcha`／`stopReason` 含「驗證」／`presenceOpen()` 才呼叫 `startScript`（它自己擋已有一場、場數用完、沒劇本）；任何一項不符合就放棄這次、不補排。**最小間隔看時鐘**：`recordScriptStart` 把開場的時間（`Date.now()`）記進 `chatScriptState.lastAt`（和場數、最近用過的劇本一樣，別的遊戲分頁寫的經 `storage.onChanged` 同步、重新整理也在），手動與自動、A 與 B 的場都算，停掉練功的期間照樣在走；測試要把頁面的 `Date.now` 也快 `SCALE` 倍（`soloA({ fastClock: true })`，只有測時鐘的測試開，不然快到幾小時之後跨日會讓每日場數歸零）。`syncScriptAuto` 在 `startTriggers`、`stopTriggers`（所以 `stopEverything`、`retire` 也會取消）與 `chatScript` 設定變動時呼叫，條件消失就清計時器、再成立重新暖機；換了對方 ID（不分大小寫）也重新暖機；`rollScriptAuto` 每次也自己檢查 `scriptAutoWanted`（雙重保護）。`STATUS` 多回 `chatScriptAuto: { phase: 'warmup', secondsLeft } | { phase: 'rolling' } | null`，設定頁狀態行（`describeStatus` 的 `auto`、`everyMin`）據此多寫一段；依賴提示在欄位大於 0 時：不是 A 或沒填對方 ID 是警告、另有一條說明何時作用。測試在 `tests/integration/game/chat-script-auto.test.js`（`soloA`：假遊戲對每個送出的指令回一行，否則縮小後的 8 秒看門狗會停掉練功組）。
- B 端：來訊名稱是 `暱稱(ID)`，取括號裡的 ID（`partnerIdOf`，小寫比對）對上設定的對方 ID，不靠暱稱（和聊天回覆的 `personKey` 一致）。沒有進行中的一場時，`bestStart` 拿來訊對所有劇本第一輪（必須是 A）的每一則比，相似度（重用 `CatworldChatReply.similarity`）達 `MATCH_THRESHOLD`（0.8）且最高的那份才開始；今天場數用完不接新場。進行中就用 `createSession().hear` 和預期的那一輪比：同一輪有好幾則時，先比預期的下一則、比不上再比同一輪的其他則（掉了一則仍跟得上），**收到最後一則才回**，前面的則收下不回（`partial`）。比不到劇本就回 false，這則來訊交還給原本的聊天回覆流程。**進行中的一場比不上時（A 重新開了一場、B 還停在舊的那場，最久等 `SCRIPT_WAIT_MS`），B 要再用 `bestStart` 看這句是不是哪份劇本的開場，是就作廢舊的一場（`cancelScript`）改接新的**，不然新的開場句會被舊的那場擋掉、B 不回話（`tests/integration/game/chat-script.test.js` 擋）；B 有來訊卻沒接話時，console 會寫 `[catworld] 劇本：對方的來訊沒接話（原因）`。**開場句彼此不能太像**，否則 B 會認錯劇本（`tests/unit/chat-script-content.test.js` 擋）。
- 擬真計時（常數在 `chat-script.js` 開頭，隨機數可注入）：每一則送出前都等 `sendDelayMs(這一則的文字)`（依字數等比：每個字 `SEND_MS_PER_CHAR`＝1 秒，5 個字 5 秒、20 個字 20 秒，再乘上 ±`SEND_JITTER`＝20% 的隨機，夾在 `SEND_DELAY_BOUNDS`＝3～30 秒之間；字數用字元數；第一則從收到對方訊息或 A 按開場算起，同一輪後面的則從上一則送出算起）；錯字後補的那則更正只比錯字那則晚 `correctionDelayMs`（`CORRECTION_DELAY_MS`＝1～2.5 秒，上限一定要比對方最快的回覆 `SEND_DELAY_BOUNDS` 的下限 3 秒早，否則會變成「錯字、對方回話、更正」）；每一輪以 `typoRate` 的機率在某一則（至少 `TYPO_MIN_LENGTH`＝6 字）換掉一個字（`addTypo`：優先換常見誤用字，只選「換了之後相似度仍達 0.8」的位置，所以對方仍認得），緊接著補一則「*正確的字」；對方的「*字」更正（`isCorrection`）在這一場進行中、或剛收到對方一則的 `CORRECTION_WINDOW_MS`（15 秒）內，收下不回。
- 送出：每一則各排一個計時器，到時 `startMacro('tell <ID> <台詞>', 'script')`（算 `active()`、遵守指令間隔、閒置時也送得出去，所以不走 `queueCommand`），送出後 `chatLimiter.noteSent`，遊戲回印的「你告訴…」行才會被認成自己送的。最後一輪的最後一則送出後這一場才算結束，等待送出的期間場次還在。
- 與聊天回覆隔離：`createRecorder` 的 `claim`（每句非空來訊先問 `hearScript`，被劇本認領的不記成配對、不呼叫 `onIncoming`，所以也不進密語區、不觸發自動回覆）；我方送出的回印行靠 `isOwn` 認出、不記成回覆；聊天回覆的冷卻與每小時上限不計劇本。
- 場數與狀態：`chrome.storage.local.chatScriptState`＝`{ date, count, recent }`（`normalizeState`），`date` 是本機日期（`dayKey`），跨日 `count` 歸零，`recent` 舊的在前、最多 5 個；A 開場與 B 開始接話都記一場（`recordStart`），別的遊戲分頁寫的經 `storage.onChanged` 同步。`STATUS` 多回 `chatScript: { scriptId, turn, total, done, phase } | null`（另有 `chatScriptAuto`，見自動開場）（`phase` 是 `say` 或 `wait`），遊戲頁面板的「劇本」列（`.script-line`，`scriptSummary()`：功能沒開是空字串、整列 `hidden`，開著就是同一個 `describeStatus` 的文字；`STATUS` 與面板共用 `scriptSessionStatus`、`scriptAutoStatus`）和設定頁狀態行是 `describeStatus`（今天 N/M 場；目前進行到第幾輪、正在說或等對方回）。
- **中止一律靜默、不補送任何收尾**（`cancelScript`：清計時器與排隊中的台詞、`cancelMacros('script')`）：等對方下一輪超過 `SCRIPT_WAIT_MS`（3 分鐘）、`beginCaptcha`、`stopEverything`、`retire`、功能被關、角色或對方 ID 被改、送出那一刻驗證碼辨識中或 `stopReason` 含「驗證」或 `startMacro` 回 false。重新整理遊戲頁或擴充功能重新載入就結束，不續播。新增會停下一切的入口要記得叫 `cancelScript`。
- 內容：範本 `docs/templates/shared-chat.csv`，README 的標題列與它由 `tests/unit/shared-data.test.js` 對照；第二批 20 份（6 時事加 14 常青）在 `docs/data/chat-scripts-w46.csv`，第一批 12 份在 `docs/data/chat-scripts-w45.csv`（貼進試算表用，備註有來源與日期，時事劇本要定期換新），說明在 `docs/data/README.md`。劇本好不好沒辦法測，`tests/unit/chat-script-content.test.js` 只擋客觀條件：通過驗證規則、7～8 輪且 A 先說、題材分佈、備註有日期與連結、不碰政治傷亡災難的字眼、不用「這禮拜」「下禮拜」這種過幾天就錯的寫法、開場句彼此相似度低於 0.8、內建劇本不綁時間。新的一批用 skill `/chat-scripts`（`.claude/skills/chat-scripts/SKILL.md`）產，交付前跑 `node tools/check-chat-scripts.js <csv> [--turns 7-8]`（同一套客觀條件，開場句和 `docs/data` 所有批次與內建劇本比；新批次不另外寫測試）。推上共用試算表用 `node tools/push-chat-scripts.js <csv> [--dry-run]`（先跑檢查器；接收端是 `tools/apps-script/push-chat-scripts.gs`，獨立的 Apps Script 網頁應用程式，同一個劇本ID 整份取代、其他列不動、寫成純文字；網址與密碼只在環境變數或 `.scratch/chat-push.json`；部署步驟在 `docs/data/README.md`「推上試算表」；測試 `tests/unit/push-chat-scripts.test.js` 在 vm 用假的 SpreadsheetApp 跑 `.gs`）。
- 測試：`tests/integration/game/chat-script.test.js`（整個 content script 在 jsdom 裡開兩個頁面，`pair()` 把一頁送出的 tell 中繼成另一頁的私聊來訊，走完整場：開場接話、拆則、錯字與更正、各種中止、場數、與聊天回覆的隔離）、`tests/integration/background/chat-script-background.test.js`（`CHAT_SCRIPTS`）、`tests/integration/settings/chat-script-settings-ui.test.js`（設定頁）、`tests/unit/chat-script-content.test.js`（內容）、`tests/unit/shared-data.test.js`／`shared-background.test.js`／`shared-settings-ui.test.js` 裡 chat 的部分。**真實遊戲裡 `tell` 的行為與兩台真機之間的時間差，jsdom 驗證不了，只能實測。**

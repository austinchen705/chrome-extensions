# 設定頁

- 面板的 ⚙ 由 `background.js` 把 `popup.html?tab=<遊戲分頁 id>` 開成分頁並記在 `storage.session`，再按一次關閉；`popup.js` 看到 `?tab=` 就控制那個遊戲分頁（`getTab`）並加上 `body.page` 樣式。popup 與設定頁是同一份 HTML/JS，改一份兩邊都會變。設定頁開在背景分頁時，自己的 `setInterval(refreshLive, 1000)` 會被 Chrome 降頻，所以遊戲頁的 `renderPanel` 在「定時開關、任一組觸發開關、巨集有沒有在跑」變了時會送 `STATE_CHANGED`（只送給擴充功能的頁面），設定頁收到（且來自它控制的那個遊戲分頁）就立刻 `refreshLive()`；定時那一頁的狀態文字平常只在按自己的按鈕時改，`refreshLive` 在開始／停止翻轉時才跟著改（不蓋掉錯誤訊息）。
- 設定頁的項目多，全部用摺疊收起來：下方各個設定區塊、定時分頁的固定／隨機指令、各組的「命中後隨機延遲」與「安全機制」都是帶 `id` 的 `<details class="fold">`（預設收起；`id` 是記住展開狀態的鍵，新增區塊一定要帶）；展開狀態存在 `chrome.storage.local.popupFolds`（`{ id: 是否展開 }`，`toggle` 事件不冒泡，所以在 document 用捕獲階段聽，每次存全部）。固定／隨機指令的標題由 `updateItemSummary` 寫成「固定指令（N 項）：指令…」。觸發規則卡片（`ruleCard`、`keywordCard`）收成標頭加一行摘要，其餘欄位放在 `.rule-body`（`foldRule`）：**`#rules-<組>` 的子節點必須仍然是卡片本身，`readSettings` 靠 `data-f` 在卡片裡找欄位，收起來的欄位照樣會被讀與存**；沒填內容的規則（`isBlank`）與按「＋」新增的規則直接展開。測試在 `tests/integration/settings/settings-fold-ui.test.js`。
- **分頁與版面**：分頁是定時送出、隨機送出、Idle、戰鬥觸發、練功觸發、**設定**（觸發分頁是 JS 後加的，所以 `tab-settings` 按鈕在建立完觸發分頁後重新放到最後；記住的分頁可以是 `settings`）。觸發分頁（`<template id="triggerPaneTemplate">`）只放該組自己的東西：數值讀數、規則清單（包在 `fold-rules-<組>`，標題 `rulesSummary-<組>` 由 `updateRulesSummary` 寫成「觸發規則（N 條，M 條關閉，⚠ K 條被停用）」，新增規則的按鈕在摺疊裡面；`#rules-<組>` 的子節點仍然是卡片本身）、命中後隨機延遲、安全機制、開始／停止、使用說明（`fold-help-<組>`）。18 個全域區塊（`sec-*`）全在 `data-pane="settings"` 底下，分成四個 `details.group`（`grp-assist` 遊戲輔助、`grp-auto` 自動回覆與獎勵、`grp-alert` 警報與安全、`grp-data` 資料與連線），巢狀的 `details` 也要帶 `id`。全域的使用說明（`fold-notes`）放在所有分頁的外面。「測試送出 ps」在定時分頁（結果顯示在那一頁的狀態列）、「測試提示音」在 `sec-alert`、「悟招清單」在 `sec-features`。新增全域區塊放進設定分頁的某一組，不要放進觸發分頁。
- **功能依賴提示**（`popup.js` 的 `DEPENDENCIES`、`updateHints`）：某個功能要靠另一個功能或欄位才會作用時，在用到它的區塊最上面（`summary` 後面）寫出原因；`warn`＝現在這樣設定不會作用（琥珀色「⚠」，區塊標題也加 `has-dep` 讓收起來時看得到），`info`＝只是說明。條件只看畫面上的欄位，`change`、`input` 與每秒的 `refreshLive` 都會更新。**新增一列前要先確認程式裡真的有這個前提**（例如密語區塊只是顯示，劇本對話不靠它；手機通知沒填憑證設定頁本身就開不起來，所以不用提示）。目前的列：密語顏色、怪物分級（要怪物查詢）、主要武器與裝備比較（要裝備比較）、拜師（要拜師功能）、裝備資料庫（沒開裝備比較就沒有「讀取目前穿著」）、地圖巡怪、劇本對話（沒填對方 ID、每天 0 場、與密語／聊天回覆的關係）、停止關鍵字（清單空）。測試在 `tests/integration/settings/settings-layout-ui.test.js`。
- **寬螢幕版面（只在 `body.page`，小視窗不受影響）**：斷點在 `popup.html` 的 `@media`：小於 900px 與以前相同（寬 460px 置中）；900px 起 `body.page` 放寬到最寬 1500px，用整頁寬度的是觸發分頁的規則清單、設定分頁的大組（見下兩條）與 `#sec-hunt`（地圖巡怪）的 `#huntFields`，頁首與定時、隨機、Idle 分頁、觸發分頁的其他區塊（狀態、數值讀數、命中延遲、安全機制、開始停止、說明）維持 460px 靠左；`#huntFields` 用 CSS grid（`grid-template-columns` 2 欄，1400px 起 3，`align-items:start`），每個群組摺疊固定在自己的欄，展開只讓那一列變高。三處（規則卡片、設定分頁區塊、巡怪群組）都**不用 `column-count`**：多欄版面會在某一項展開時重新平衡，項目跳到別的欄。群組的欄位放在 `popup.js` 產生的 `.hbody`（摺疊本身不動，id 照舊），`.hbody` 是 `auto-fill` 格線（每格至少 190px）：`.hfield.hlong` 與 `.hrow`（內部自己兩欄）佔整列，其餘短欄位並排。長欄位由 `CatworldMapHunt.isWideField` 決定：欄位表 `type` 是 `text`，或標了 `wide: true`（選項字很長的下拉，目前 `fightMode`、`timeSource`）；不要在樣式裡寫欄位名稱。jsdom 算不出排版，排版用 headless Chrome 截圖驗證（460、1100、1600 與小視窗）。
- **觸發規則卡片分欄**（`body.page` 且 900px 起，1400px 起 3 欄）：`popup.html` 對規則清單容器 `#rules-<組>` 本身下 `display:grid`（由左往右再換列），**不能在卡片外多包一層**（`readSettings` 靠清單的子節點是卡片、卡片裡的 `data-f` 讀欄位）；標頭前面用 CSS 計數（`counter(rule)`）編號，順序是左到右再下一列；展開的卡片留在自己那一欄、只讓那一列變高。新增規則的按鈕在摺疊裡、清單下面整列。觸發分頁其他區塊靠 `#triggerPanes > [data-pane] > :not([id^="fold-rules-"])` 限 460px。
- **設定分頁區塊分欄**（`body.page` 且 900px 起，1400px 起 3 欄）：4 個大組（`details.group`）展開時自己 `display:grid` 2／3 欄（`details` 的內容在 `::details-content`，要設 `display:contents` 組內 `details.alertbox` 才會成為 grid 項目），組標題與 `#sec-hunt` 用 `grid-column:1 / -1` 佔整列（所以巡怪的整頁寬度與群組並排照舊）；大組的摺疊、id、依賴提示都不變。新增區塊放進某一組即可，不用另外寫版面樣式。
- 設定頁沒有儲存鈕，每改一個欄位就存進 storage：觸發分頁是 `root.addEventListener('change', save)`，定時與隨機分頁是 `saveTimerSettings`（兩頁的 `change` 與刪除一列都存同一份 `settings`，不用按開始；按開始時才檢查秒數是否合理，遊戲頁讀到時再由 `timer-settings.js` 整理）；遊戲頁的 `settings` 與 `group.config` 只在載入時讀一次，所以面板的「開始」（定時、各組觸發）按下去要先重新讀 storage 再開始，不然跑的是改之前的舊設定（測試 `tests/integration/game/panel-start-fresh-settings.test.js`）。

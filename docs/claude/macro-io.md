# 巨集匯入匯出

- 遊戲把巨集存在頁面的 `localStorage.MACROS`（長度 90 的陣列，每格 0 或 `[按鍵值字串, 指令字串]`；來源是遊戲的 `/js/web.js`，遊戲頁 `/web` 對使用者可能回 403，但 `web.js` 讀得到）。遊戲用閉包裡的私有陣列管理巨集視窗，外部改輸入框值寫不進去，所以要改巨集只能直接寫 `localStorage.MACROS`，遊戲要重新整理才會重讀（而且重新整理前在遊戲視窗改任何巨集，遊戲會用記憶體裡的舊內容整份存回去、蓋掉寫入），不能靠模擬輸入事件。
- `macro-io.js` 不碰 DOM 與 `chrome.*`（`readMacros` 讀遊戲存的巨集一律回 90 格並帶 `status`：`ok`／`missing`／`damaged`，壞資料不丟例外，空字串遊戲也當作沒有；`exportText` 產生 `{ version, macros, notes }`，備註只收 1～90 列有字的文字；`parseImport` 檢查匯入文字，`countFilled` 數有內容的列），`macro-io-ui.js` 管設定頁「遊戲巨集匯入匯出」（`popup.html` 的 `sec-macro`，在「資料與連線」組）的按鈕與訊息。`macro-io.js` 要在 manifest 的 content script 與 popup 備援注入的 `files`（`expandMacroRefs`、`macro-resize.js` 用到），也在 popup.html；`macro-io-ui.js` **只在 popup.html 載入**，遊戲頁不載入。設定頁讀不到遊戲分頁的 `localStorage`，所以 `popup.js` 注入的 `deps.readRaw`／`deps.writeMacros` 走 `send`（`chrome.tabs.sendMessage` 給這個設定頁控制的遊戲分頁，連不上會備援注入）送 `MACRO_READ`／`MACRO_WRITE`，由 `content.js` 的 `onMessage` 代讀代寫（閒置時也回應；寫入不檢查內容，還原要原樣寫回遊戲讀不懂的備份）；備註與備份是 `chrome.storage.local`，設定頁直接讀寫。所有 deps 都是 async。讀的例外帶 `unreachable`（連不上遊戲分頁）時匯出直接報錯、不匯出空的；寫的例外分兩種：遊戲分頁回 `ok:false`、找不到或連不上（`UNREACHABLE` 的錯誤字）＝確定沒寫，送出後斷線、沒收到回覆＝`unknown`，當成寫進去了（警告玩家重新整理看看，**不把舊備份放回去**，新的那份可能是唯一的回頭路）。
- 匯入檢查（`parseImport`，整份通過才回正規化的 90 格與備註，否則回說明哪裡不對的錯誤）：JSON 物件、`version` 是 1、`macros` 最多 90 格（少的補空格）、每格 0 或 `[按鍵值, 指令]` 兩段文字、按鍵值**可以是空字串**（遊戲真的會存「按鍵空、指令有字」，往返一定要能過）或 1～4095 的整數、指令最多 1000 字、兩列不能用同一個按鍵值（空的不算）、備註鍵 1～90 值最多 200 字（只有空白的略過）、不認得的欄位忽略，不套指令白名單（這是自己的巨集）。**按鍵值只檢查範圍，不保證按得出來**（遊戲真正能產生的組合比 1～4095 少，寫進按不出來的值不會弄壞遊戲，所以不收緊，也避免依賴 `macro-wait.js` 的按鍵表）。
- 備份與還原：確認匯入時，**先**用 `makeBackup(原始文字, 備註, 時間)` 把遊戲現在的巨集（原樣的字串，壞掉也原樣留，沒存過就留 90 個空格）與備註存進 `chrome.storage.local.macroBackup`（只留一層，匯入一次覆蓋上一份，不進匯出），**備份寫不進去就不匯入**（讀不到目前的巨集或備註就沒有完整的備份，同樣不匯入）；寫遊戲的 `localStorage.MACROS` 失敗時把**原本那份備份放回去**（新備份只是「現在的樣子」，匯入沒發生就不能讓它蓋掉舊備份），只有備註寫失敗時不放回（巨集已經換了，新備份才是回頭的路）；「還原上一份」按鈕在匯入框裡（面板「巨集」列寬度只有 310px，放不下第四顆按鈕），有備份才可按（壞掉的備份也讓它按得下去，按了才說明哪裡壞），讀回後走 `parseBackup` 檢查，壞掉（不是物件、巨集文字不見）就說明原因、什麼都不動；巨集文字本身遊戲讀不懂（`readMacros` 判 `damaged`）仍可還原（那是唯一的原樣備份，由玩家決定），但確認文字要先警告遊戲可能載入失敗（遊戲載入時 `JSON.parse(localStorage.MACROS)` 外面沒有 try/catch）；確認後用匯入同一條寫入路徑（`apply`：先 `localStorage.MACROS`、再備註）寫回，還原後備份保留。
- 匯入流程在 `macro-io-ui.js`（`attach` 拆成 `setupExport`、`setupImport`，訊息區是 `createMessage`；匯入與還原只有確認文字開頭、失敗與完成訊息、要不要先留備份、要不要清貼上框不同，集中在 `KINDS` 表，匯入前留備份在 `backupCurrent`）：貼文字 → `parseImport` → 通過才顯示確認（「將取代 N 列」與重新整理、403、蓋掉匯入、多分頁的警告）→ 確認後先寫遊戲的 `localStorage.MACROS`（寫不進去就停，什麼都沒動）再寫備註；備註用 `macroNotesWriter: 'macro-io'` 寫，**寫入者不能是備註模組自己的隨機代號**，備註模組才會把它當成別處的改動、直接更新畫面上的備註框（`storage.onChanged` 在寫入的那個頁面也會觸發，備註模組靠代號忽略自己的寫入）。待確認的檢查結果在貼的文字一改、收起匯入框或取消時作廢，確認鈕只套用「檢查當下」的結果，不重新解析；顯示確認前要先問遊戲分頁現在有幾列（要等），等的期間作廢過就不顯示（`askToConfirm` 的 `ticket`，`dropPending` 每次換）。訊息的顏色用設定頁共用的 `msg-error`／`msg-warn`。匯入的成功訊息與錯誤要一直留著（不自動收起），因為要提醒重新整理；匯出成功的訊息才會自動收起。檢查通過時要先收掉上一則訊息，免得舊的錯誤和確認框並存。
- 面板的「巨集」列常駐顯示（只剩「停止」），狀態文字沒有巨集在跑時要清成空的。匯出的剪貼簿用按鈕所在 document 的視窗，複製失敗要把文字放進可手動複製的框。
- 測試：`tests/unit/macro-io.test.js`（純函式，邊界案例都放這裡）、`tests/integration/settings/macro-io-ui.test.js`（jsdom 載入真正的 popup.html，假的 `chrome.tabs.sendMessage` 扮演遊戲分頁的 `MACRO_READ`／`MACRO_WRITE`，假的剪貼簿）、`tests/integration/game/macro-io-messages.test.js`（jsdom 載入整個 content script，直接呼叫訊息監聽：`MACRO_READ`／`MACRO_WRITE` 的回覆與 `localStorage.MACROS`，面板沒有匯出匯入按鈕）；真實的剪貼簿、分頁訊息、遊戲重新整理後是否讀到新巨集只能在真實瀏覽器驗證。

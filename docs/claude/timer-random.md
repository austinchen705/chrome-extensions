# 定時分頁的固定指令與隨機指令

- **定時（固定指令）與隨機指令是兩個獨立的功能**：`content.js` 的 `running`（定時）與 `randomRunning`（隨機）各自開始、停止（`START`／`STOP`、`START_RANDOM`／`STOP_RANDOM`，storage 的 `running`、`randomRunning`，STATUS 都回），送出佇列與巨集的來源（owner）分別是 `timer`、`random`，停止時只取消自己的；`active()` 兩個都算；`stop`／`stopRandom` 結束時用 `finishStop`：還有別的功能在跑只 `pumpQueue`，都沒在跑才 `clearTimers`（清共用的送出計時器、看門狗、驗證碼狀態）。`stopEverything` 兩個都停。設定仍存在同一個 `settings`（`fixedItems`、`randomItems`），設定頁分兩個分頁、面板分兩列。
- **Idle（全域暫停）**：設定存在 `chrome.storage.local.idleSettings`（`{ everyMin, everyMax, durMin, durMax }` 分鐘，`timer-settings.js` 的 `normalizeIdle`／`idleMs`，不合法退回預設、最大不小於最小），`content.js` 的 `idleState`（`{ phase: 'idling' | 'working', at, timer }`）與 `idlePaused`：`startIdle` 先 `beginIdling`（暫停＝清掉固定與隨機的計時器；兩組觸發的引擎 `tick` 與關鍵字 `onText` 在 `idlePaused` 時不呼叫），`endIdling` 恢復（`startFixedItems`／`scheduleRandomCommand`／引擎 `tick`）再排下一次 idle。`startFixedItems`、`scheduleRandomCommand` 在 `idlePaused` 時不啟動（idle 中才按開始，等 idle 結束再跑）。`cancelIdle({ resume })`：停止 idle 預設讓暫停的繼續，`stopEverything` 與 `retire` 用 `resume: false`。已經在跑的巨集與佇列裡的指令不取消（照送完）。訊息 `START_IDLE`（帶 `settings`）、`STOP_IDLE`，STATUS 回 `idle: { phase, at } | null`。測試在 `tests/timer-random-idle.test.js`。

- 設定格式是 `settings.fixedItems` 與 `settings.randomItems`，都是 `[{ command, minSeconds, maxSeconds }]`，轉換與抽選在 `timer-settings.js`（content script 與 popup 共用，manifest、popup.html、popup 的備援注入都要載入，且要在 `content.js` 之前）。固定指令每一項各自循環（`content.js` 的 `fixedRuns`：開始時先送一次，之後在自己的秒數內隨機等再送，彼此不等；`STATUS` 回 `fixed: [{ command, at }]`）；隨機指令先挑一個再等它自己的秒數。
- 舊格式由 `normalizeFixedItems`（`commands` + `minSeconds` / `maxSeconds`：轉成一項、指令用 `;` 接起來，才維持「每輪全部依序送出」；`commands` 也沒有時給預設的 `ps;px`）與 `normalizeRandomItems`（`randomCommands` + `randomMinSeconds` / `randomMaxSeconds`）轉換；**不能在 `content.js` 的預設設定裡放 `fixedItems`、`randomItems`**，否則空陣列會蓋掉升級前存下的舊設定（測試 14i、15i 與 `tests/timer-settings.test.js` 會擋）。

# 驗證碼圖形偵測

- 偵測規則在 `captcha-art.js`（`artText`、`looksLikeAsciiArt`、`looksLikeNoiseCaptcha`、`createWatcher`；content script 與測試共用，manifest 與 popup 的備援注入都要載入、且在 `content.js` 之前）。偵測規則都是看「連續好幾行」，而遊戲輸出常分成好幾批新增文字到達（一張圖可能被切成一行一批），所以 `content.js` 的 `captchaObserver` 不能只看單一批：一律經 `artWatcher.feed`（把最近 5 秒的新增文字接在一起、最多 120 行，偵測到就清空；`armDetection` 重新開始時也清）。
- **真人驗證（`#presence`）**：遊戲伺服器推 `presence.challenge` 後，遊戲把 `#presence` 的 `invisible` 拿掉並倒數 60 秒，要玩家點選「和左側範例相同的圖形」（圖是 `#presence_image`，向遊戲的 `/presence` 另外要；遊戲還會回報點擊是不是真的滑鼠事件 `isTrusted`、答題時間、滑鼠移動次數，並同時跑 Cloudflare Turnstile）。**圖不在 `#content` 的文字輸出裡，所以 `captchaObserver` 看不到**；`content.js` 另用 `presenceObserver` 只看 `#presence` 的 `class`：從隱藏變成顯示的那一刻 `stopAndAlert`（原因含「驗證」，所以 `stopEverything` 之後要玩家手動按開始才會再送指令；定時、兩組觸發、巨集、劇本對話都被取消）。**不辨識、不代點、不偽造事件**（那是遊戲專門分辨真人的驗證，不能去繞它）；解除後不自動恢復。出現時警報之後另外 `reportPresenceSample`：等 `#presence` 裡的圖載好（最多 `PRESENCE_IMAGE_WAIT_MS` 5 秒）再把整塊 `#presence` 的 HTML（`<img>`／`<canvas>` 轉成 data URL 嵌進去，轉不了＝跨來源就留原網址；超過 `PRESENCE_SAMPLE_MAX` 45000 字退回不嵌圖，還是太大就不收，試算表一格上限 50000）用同一個 `CAPTCHA_SAMPLE` 送去收集，`outcome` 是 `presence`、answer 空、attempts 0，所以 Apps Script 與「樣本」分頁不用改（hash 去重照舊）；**圖的真實格式沒有樣本**，第一次遇到要看試算表那列與 console `[catworld] 真人驗證樣本`。只存檔，不能拿來代答。只在「隱藏→顯示」警報，其他 class 變動與顯示中的重複變動不再警報；載入時就顯示著的不算新出現、不警報，但驗證開著的期間 `sendCommand` 一律不送（`presenceOpen`，送出被拒會讓 `pumpQueue` 停下一切，所以定時、觸發、巨集、劇本等所有入口都擋得住，關掉後再按開始才會動）；頁面上沒有 `#presence` 就不觀察；`retire` 要一起 `disconnect`。測試在 `tests/integration/game/presence-check.test.js`（底座的頁面骨架有 `#presence`）；遊戲真正推 `presence.challenge`、Turnstile 與點選答題只能在真實遊戲驗證。
- 診斷：驗證碼偵測沒反應時看遊戲頁 console（篩 `[catworld]`）：`疑似驗證碼的批次`（印這一批的行數、長行數、背景色標記數與是否偵測到）、`驗證碼自動辨識：送出 …`／`通過`／`失敗，字形矩陣`。不要為了這個把規則放寬到會誤判一般輸出。
- 測試：`tests/integration/game/captcha-art.test.js`（jsdom，用 `tests/fixtures/captcha/` 的真實樣本：英數亂碼塊、B3 背景空白拼的數字圖、一般輸出；分批大小 1～4 行都要抓到、一般輸出逐行餵也不能誤判、隔太久的片段不能接在一起）。新增驗證碼樣式時先把真實輸出放進 fixtures 再改偵測。
- 自動辨識在 `captcha-grid.js`（`decodeHtml` 吃遊戲輸出的 HTML：背景色 `B1～B9` span 裡的每個字元都是方塊，空白或亂碼文字都算，沒有 span 時 `@ $ # % & * █` 符號本身是方塊但只限整行同一種符號的行（一般輸出的 `(100%)` 不算），數字可能是方塊本身也可能是方塊間的空洞；圖是「連續有填色的列」的某一段：依填色多寡逐段試，第一段每個字形都認得的就是圖（圖前幾秒的狀態卡、背景色物品名，以及圖印完後 1 秒內接著印、比圖還大的整片底色公告橫幅，都不會影響反相判定或被當成圖），全都認不出就回填色最多那段的結果；模糊比對門檻 0.9，沒把握回 `?`，曾以 0.86 把 5 猜成 6；`LIBRARY` 是以整個字形矩陣為鍵的精確模板庫，查不到才做 5x7 模糊比對；content script、測試與 `tools/captcha-grid.js` CLI 共用，manifest 與 popup 備援注入都要載入、排在 `captcha-art.js` 之後）。`content.js` 的流程：偵測到圖或提示 → `beginCaptcha` 暫停送出佇列、把後續批次的 HTML 接上去（偵測看 artText，辨識要原始 HTML，`artWatcher.feed` 兩個都收）→ `CAPTCHA_QUIET_MS` 沒新輸出才 `solveCaptcha`，讀到數字後再隨機等 `CAPTCHA_SEND_DELAY_MS` 範圍內（3～10 秒）才送出（等的期間 `answer` 仍是空的，新輸出照樣接上去重新等靜默）→ 看門狗的 `NO_REPLY_MS` 沒回應＝答錯（遊戲答錯不回應）→ `retryCaptcha` 重送同一答案到 `CAPTCHA_MAX_ATTEMPTS` 次才 `stopAndAlert`；有回應就 `endCaptcha` 恢復送出。讀不出數字直接停，矩陣印在 console。偵測器在第 5～8 行就命中而圖有 10～16 行，所以不能在命中那一刻解；偵測器命中那一刻的視窗已含當批，再接一次會讓圖重複。
- 測試：`tests/unit/captcha-grid.test.js`（解碼：合成字形、八種真實版面）、`tests/integration/game/captcha-solve.test.js`（整個 content script 在 jsdom 裡跑、計時器縮小 `SCALE` 倍：答案送出、有回應恢復、沒回應重送 3 次後停、通知送不出去也要停、領獎提示併進同一輪、讀不出就停）。底座在 `tests/helpers/game-page.js`。新字形：先把真實輸出放進 fixtures，用 `node tools/captcha-grid.js <檔> --debug` 看矩陣，確認後貼進 `LIBRARY`。
- 樣本收集：`content.js` 的 `reportSample` 在每回合結束（`endCaptcha`＝passed、`retryCaptcha` 滿次數＝silent、`solveCaptcha` 讀不出＝unknown）送 `CAPTCHA_SAMPLE`（`{ outcome, answer, attempts, html }`），不等結果、送不出去不影響流程。`background.js` 的 `uploadCaptchaSample` 讀 `chrome.storage.local.captchaSampleUrl`（`onInstalled` 在這個鍵從沒設定過時帶入 `CAPTCHA_SAMPLE_DEFAULT_URL`＝作者的收集表，和 `sharedSources` 同一個 handler；空的就不碰網路；**content script 不讀這個鍵**），補上 `version` 後以 `text/plain` POST 到 Apps Script（JSON 會觸發 CORS 預檢而 Apps Script 不回應預檢；POST 會 302 到 `script.googleusercontent.com`，所以 `host_permissions` 要同時有 `script.google.com` 與 `*.googleusercontent.com`），15 秒逾時、不重試，結果存 `storage.session.captchaSampleLastResult` 給設定頁顯示；設定頁只收 `https://script.google.com/macros/` 開頭的網址（別的主機沒權限、會悄悄失敗）。Apps Script 的 `doPost` 範例與部署步驟只寫在 README「驗證碼樣本收集」。測試：`tests/integration/game/captcha-solve.test.js`（三種結果各送一筆、樣本的 HTML 可直接解碼）、`tests/integration/background/captcha-sample-background.test.js`（vm 執行 background：安裝時帶入預設網址、有網址才打、只收遊戲頁、失敗不丟例外且不影響警報、逾時）、`tests/integration/settings/captcha-sample-ui.test.js`（設定頁欄位與結果列）。

# 設定雲端同步

- 規格與票在 `.scratch/cloud-settings-sync/`（不進 git）。伺服器是獨立的 Apps Script 網頁應用程式 `tools/apps-script/settings-sync.gs`（作者部署，步驟在 `README.md`「設定雲端同步（作者部署）」），每個遊戲角色在作者的 Google Drive 存一個 `<角色>.json`。
- 請求：`POST` JSON `{ action: 'upload' | 'download' | 'info', account, password, payload? }`。回應一律 HTTP 200：`{ ok: true, ... }` 或 `{ ok: false, error }`，`error` 是 `bad-password`、`not-found`、`too-large`、`bad-request`、`server-error`（Drive 讀寫失敗、存檔壞掉）。`upload` 回 `{ updatedAt, claimed }`，`download` 回 `{ payload, updatedAt, exportedWith }`，`info` 回 `{ updatedAt, exportedWith }`；`updatedAt` 是 ISO 字串，`exportedWith` 取自 `payload.settings.exportedWith`。
- `payload` 是 `{ settings, macros? }`：`settings` 是 `catworld-settings` 格式的物件（見設定備份，`format` 必須是 `catworld-settings`），`macros` 可省略、有的話是物件。請求本文超過 1 MB（1048576 字元）回 `too-large`，在解析 JSON 之前檢查。
- 角色名稱：去前後空白、英文大寫轉小寫，只收文字（含中文）、數字、`_`、`-`，長度 1～40，其他一律 `bad-request`。密碼是 1～200 字元的字串。
- 認領：角色檔不存在時 `upload` 建立並存 `salt`（`Utilities.getUuid()`）與 `hash`（SHA-256(salt + 密碼) 的十六進位）；之後 `upload`／`download`／`info` 都比對 `hash`，不對回 `bad-password`。`download`／`info` 對沒有的角色回 `not-found`，不建檔。忘記密碼就由作者在 Drive 刪掉那個角色的檔。
- 資料夾：指令碼屬性 `FOLDER_ID` 有值且開得到（沒被丟進垃圾桶）就用；否則找／建 My Drive 根目錄的 `catworld-settings-sync`，並把它的 ID 存進 `FOLDER_ID`（改名、搬家後仍找得到）。通過檢查的請求整段在 `LockService.getScriptLock()` 下執行。
- 測試：`tests/unit/settings-sync-gs.test.js`（在 vm 用假的 Drive 等服務執行 .gs）。部署後的網址與權限只能由作者實際呼叫驗證。
- 設定頁（票 02）：`popup.html` 的 `sec-cloud`（「資料與連線」組）加 `popup.js` 的「雲端同步」區塊；和伺服器說話的純函式在 `cloud-sync.js`（`CatworldCloudSync`：`call` 送請求並把結果統一成 `{ ok, ... }` 或 `{ ok: false, error }`，本機失敗另有 `no-url`、`bad-url`、`network`、`timeout`、`http`、`bad-reply`；`errorText` 對照訊息；`characterFromTitle`、`formatTime`），和 `settings-backup.js` 一樣**只有 popup.html 載入**。請求從設定頁直接送（`host_permissions` 已有 `script.google.com` 與 `*.googleusercontent.com`），`text/plain` POST、30 秒逾時。`cloud-sync.js` 的 `DEFAULT_URL` 是內建網址，**目前是空的**（作者部署後只改這一個地方）；「進階」摺疊裡的欄位有填就用欄位，兩邊都空就顯示紅字「雲端同步網址還沒設定」、什麼都不送；網址要以 `https://script.google.com/macros/` 開頭。
- 角色欄：載入時讀這個設定頁控制的分頁（`getTab`），是遊戲頁才取標題「角色名 - …」的角色名，否則用上次存的；可手改。上傳：`exportData`（`secrets: false`）只含勾選的區塊，payload 是 `{ settings }`。下載：先 `info`，再 `confirm`（時間、版本、會覆蓋的區塊），再 `download`，接著 `checkImport`／`planImport`（`secrets: false`，只處理勾選且雲端有的區塊，未知的區塊與鍵忽略），最後 `applyImportPlan`（和檔案匯入共用：先備份、備份寫不進去就不寫、失敗放回）並整頁停用（`freezeSettingsPage`）。錯誤一律紅字，缺密碼、角色、區塊是琥珀字，成功不上色。
- 儲存鍵：`cloudSyncUrl` 在「共用與網址」區塊（會隨設定匯出，也會被雲端下載覆蓋）；`cloudSyncPassword`、`cloudSyncAccount`、`cloudSyncBlocks`、`cloudSyncMacros` 在排除清單（密碼不能進任何匯出或雲端資料，所以不放 `SECRET_KEYS`：那份勾選就會匯出）。
- 遊戲巨集（票 03）：區塊勾選之外另有「遊戲巨集與備註」勾選（`cloudMacros`，不在 `cloudBlocks` 裡、預設不勾，存在 `cloudSyncMacros`）；至少還是要勾一個設定區塊。`popup.js` 把遊戲巨集匯入匯出用的 deps 抽成 `macroDeps`，雲端同步共用同一份（讀寫遊戲分頁的 `MACRO_READ`／`MACRO_WRITE`、備註、`macroBackup`），先備份的步驟是 `macro-io-ui.js` 匯出的 `CatworldMacroIOUI.backupBeforeWrite(deps)`（匯入按鈕也用它，見巨集匯入匯出）。
  - 上傳（勾了才做）：`readGameMacros` 用 `readRaw`、`readMacros`、`readNotes`、`exportText`，把匯出檔同一個形狀 `{ version, macros, notes }` 放進 `payload.macros`；連不上遊戲分頁、讀不到、遊戲存的巨集讀不懂（`damaged`）、讀不到備註都是紅字、**什麼都不送**（不會只傳設定，也不會用空的巨集蓋掉雲端）。遊戲還沒存過巨集（`missing`）傳 90 個空格。
  - 下載（勾了且 `payload.macros` 有才做）：設定那一段照舊先處理（設定錯誤、備份寫不進去就整個停，巨集也不碰；設定和現在一樣或沒有勾選的區塊不擋巨集），再 `applyCloudMacros`：`parseImport` 檢查（不過＝紅字、巨集不動）→ `backupBeforeWrite`（連不上遊戲分頁＝琥珀字「遊戲分頁沒有開，請打開遊戲後再下載一次」、設定已寫入；備份寫不進去＝紅字、不寫）→ 寫遊戲的 `localStorage.MACROS`（確定沒寫成就把原本的巨集備份放回去；`unknown`＝琥珀字、不放回去）→ 寫備註（寫入者 `macro-io`）。成功訊息提醒重新整理遊戲頁；只有設定被套用時才整頁停用。確認對話框在勾了時多一句「雲端有遊戲巨集就整份取代遊戲現在的」。沒勾時上傳、下載都不碰遊戲分頁與巨集；勾了但雲端沒有 `macros` 就說明沒動。
- 測試：`tests/unit/cloud-sync.test.js`、`tests/integration/settings/cloud-sync-ui.test.js`（假的 fetch 與遊戲分頁）。真實的 Apps Script 網址要作者部署後實際驗證。

# 地圖巡怪：街景模式（掃描）

- **街景模式（掃描）**：`start({ scan: true })`（面板「巡怪」列的 `.hscan`，不用勾怪）。目標是 `graph.rooms` 裡 `mapVisited`（`{ "區域/房間": { at, state: 'seen' | 'blocked' } }`，`normalizeVisited` 讀回時過濾壞資料，`deps.visited`／`deps.markVisited`，`content.js` 的 `markHuntVisited` 排成一條讀改寫佇列）沒有的房間；`inspect` 在 `scan` 時 `l` 之後只 `learnPlaces` 與標記 `seen`（空房間也記，因為 `mapMonsters` 不記沒怪的房間）就換下一間，不 finger、不打。`learnVisit` 只補不刪（見 `docs/claude/map-hunt.md` 的自動補位置）。走不到的（`走不過去`、`走錯房間`、`走不到`）當場記 `blocked`（同一步已重送一次，不再整輪重試，使用者要求），之後的掃描也不再走（`seen`、`blocked` 都跳過，要重試就在設定頁清除「已走過的房間」；`讀不到房間` 不記，可能只是慢）；`走不過去`／`走錯房間` 時把那一步加進 `state.badEdges`，`plan` 用 `dropEdges` 把它從圖拿掉，門後面的房間直接判定走不到，不會吃 `MAX_SKIPS` 也不會一間一間等逾時。掃描強制 `loopRounds: 'off'`（不送 `time`、不待命、`endRound` 直接 `finish`「掃描完成」）；`vitals` 在 `scan` 時氣低於 `dangerBelow` 就 `goHomeAndStop`（不管補氣方式）。設定頁「地圖怪物蒐集」顯示走過與走不到的間數並可清除（`mapVisited` 在 `settings-backup.js` 的資料區塊）。**掃描的路線處理**：`learn` 恆為 on（`settings.learnExits === 'on' || scan`）；`inspect` 在 `l` 回應回來時 `deps.room()` 和目標房間不同（自己手動跑掉）就丟掉這份輸出、回 `plan`（巡怪模式一樣）；只有「試不出路」的房間第一輪放進 `state.deferred`（不記），`endRound` 掃描時把它們當成第二輪目標（`state.retried`，清掉 `badEdges`），第二輪還試不出路才 `markScan(…, 'blocked')`；試出口（`startTrial(here, want)`）先試開頭和 `want` 相同、後面接 u／d 的出口（圖上 s → su／sd），再試開頭相同的，最後才是其他；掃描的寬鬆圖經 `withReverse` 補上單向箭頭的反方向（猜的邊，輸給嚴格圖）；`試不出路` 在掃描時不計入 `MAX_SKIPS`。終南山的真實地圖樣本（使用者貼的）顯示石階那串是單向的 ↓，反方向圖上沒有。**手動蒐集在巡怪、掃描時暫停**：`map-collect.js` 的 `setSuspended(fn)`，`content.js` 注入 `() => hunt?.on()`；`MutationObserver` 與 `flush` 兩處都先看它（暫停時看到的怪不記，也不留到之後）。原因：它等 `SETTLE_MS` 才讀 `currentRoom`，巡怪走得快時會把怪記給下一間或上一間，而它只增不減；巡怪自己的 `learnVisit` 在確認走到的房間 `l` 之後才記，是準的。測試 `the manual collector pauses…`。**打怪前補掃**（`prescan` 設定，預設 on）：`start()` 在一般巡怪時，若 `graph.rooms` 裡有 `mapVisited` 沒有的房間（`seen` 與 `blocked` 都算有圖資，不補掃）就把那些房間當目標、`state.prescan = true`（`state.scan` 也是 true，所以走街景模式的路徑：照實際出口、不打、不問人、氣到危險線回家）；此時勾選的怪的房間可以一間都沒有，不擋。`endRound`（先做完第二輪重試）看到 `prescan` 就 `startHuntAfterPrescan`：`deps.readStore()` 重讀補好的資料、`huntTargets` 重算目標（和 `start` 共用），沒有目標就 `finish` 說明；有就把 `scan/prescan/learn/targets/after/round` 換成一般巡怪（`learn` 回到設定值）。`offset`（`time` 校準）在 `start` 就讀好放進 state。測試底座的 `REQUIRED` 預設 `prescan: 'off'`，不影響舊測試。**學到的邊取代圖上同一目的地的邊**：`buildGraph` 在房間的出口已讀過（`learned.exits`）時，圖上通往某間、而那一間已有學到的邊（`learned.to`）、且圖上的指令不在出口裡的邊會拿掉（圖上往 s、實際 su），否則寬鬆圖的最短路線挑到走不通的 s，要試出口卻沒有沒試過的，每個目標都「試不出路」（使用者貼的 console：站在 l6、出口 ne／su，所有目標連續略過）。`withReverse` 補猜的反方向邊時，那間已有通往這裡的邊就不補。測試 `scan: an exit already learned…`（只剩最遠一間當目標，才會走到寬鬆路線）。**卡住偵測**：`tick` 在掃描時每次讀 `deps.room()`，房間沒換、`doneWith`／`skipTarget` 也沒更新 `state.progressAt` 超過 `SCAN_STALL_TICKS`（180 秒，用 tick 數算，測試縮小計時器時會跟著縮）就 `finish` 並警報，訊息帶 `describe().text`（階段、目標、休息百分比）；`skipTarget` 在掃描時印 `[catworld] 掃描略過` 診斷行。**還沒做**：自動一區一區換區（回家＋總路徑表 `run e 5n 2o <路線>`，目前 36 個有紀錄的區域裡 14 個完全同名、9 個只有開頭相符、13 個沒有路線；入口路線落點、地圖是否自己切區都還沒有真實遊戲的驗證）、打怪前自動補掃、「已走過 N／M 間」顯示在選怪清單。

**戶外／室內紀錄**：`inspect` 讀到房間描述（掃描與一般巡怪都走 `lookRoom`，抵達描述或 `l` 的原文放在回傳的 `text`）後，呼叫 `deps.markOutdoor(here, text)`；`content.js` 的 `markHuntOutdoor` 用 `scholar.js` 的 `isOutdoor` 判斷（房間名稱行 `-`／`--` 之後第一段是描述，描述段之後、出口行之前有縮排開頭的行＝時辰／天氣句＝戶外；出口行之後、沒縮排、空白的行不算；沒有出口行回 `null` 不記；兩份描述只看最後一份），排成讀改寫佇列寫進 `mapOutdoor`（`{ "區域/房間": { outdoor, at } }`，後讀的蓋掉先讀的）。巡怪、掃描只有 `inspect` 的那次讀取會記，路過的房間不記。**手動走路也記**（`content.js` 的 `armManualOutdoor`／`watchManualOutdoor`）：玩家自己從輸入框或遊戲巨集按鍵送出「一個指令」（沒有 `;`、沒有空白，所以 `run …`、`enter crack` 不算）後 4 秒內出現「出口是」，就把這段輸出交給 `markHuntOutdoor`，等 600 ms 地圖捲到那一格再用 `currentRoom` 記；巡怪、掃描進行中不記。先看有沒有「出口是」，其他輸出直接跳過。測試在 `map-collect.test.js`（outdoor rooms: walking by hand）。設定頁「地圖怪物蒐集」列出每區戶外、室內格數，可清除；`mapOutdoor` 在 `settings-backup.js` 的資料區塊。測試：`tests/unit/scholar.test.js`、`map-hunt-scan.test.js` 的 outdoor 一組（假遊戲 `looks[房間].weather` 產生天氣行）、`tests/integration/settings/scholar-sightings-ui.test.js`。

- **找書生模式**：`start({ scholar: true })`（面板「巡怪」列的 `.hscholar`「找書生」，不用勾怪）。按下時書生助手沒開就先跑 `toggleScholarHelper`（sc／sk 檢查），檢查不過不開始；目標是 `graph.rooms` 裡 `mapOutdoor`（`deps.outdoor`，掃描與巡怪讀房間時寫的，見上面的戶外紀錄）記成 `outdoor: true` 的格子，這一區一格都沒有就 `fail('這一區還沒有戶外格子的紀錄，先掃描這一區')`（在讀 `time` 之前檢查）。強制 `loopRounds: 'on'`、`stopBeforeSpawnSec: 0`、不跨區，擬人化不作用（`humanizeOn` 看 `state.scholar`）；重生等待與校準完全沿用（`calibrate`／`waitTick`／`startRound`／`beginRound`／待命指令 `standbyAfterRound`）。`state.scholar = { active, found, idle, busySeen, offset, startAt, endAt }`：`beginRound`（和 `start` 在還沒過時間窗時直接開始）呼叫 `beginScholarWindow`，時間窗從那個重生整點起算（`scholarWindowSec`，設定頁「六脈神劍」群組，預設 180、30～900），不在時間窗內按開始就先等下一個重生。窗內照 `plan` 最近的先走戶外格子；`inspect` 在 `state.scholar` 時只讀描述（抵達描述，沒有才 `l`）、記 `learnExits`，不 finger、不打、不撿，有 `※落魄書生(dire scholar)` 就 `scholarFound`，處理完記「找書生」；`endRound` 在這個模式只標 `idle`（全看過了就不走、等窗結束）。**遇到書生**：描述有他，或 `deps.scholarBusy()`（`scholarFlow.state !== 'idle'`）為真，就停止走路（`scholarTick` 回 true），跟隨與給物品全是 `content.js` 的書生助手，引擎不重做；助手回到 idle（至少等 `SCHOLAR_GRACE_TICKS` 讓它開始處理）且現在不在試出口／看房間的半途，就 `endScholarWindow(true)`。**時間窗到了沒遇到**：記「這次重生沒遇到書生」，`standbyAfterRound({ countRest: false })`（待命指令、先走到可 ride 格子）後等下一個重生。**停止條件**：停止鈕，或 `deps.scholarOn()` 為假（助手解滿或手動關）→ `finish('書生助手關了（解滿六脈或手動關閉），已停止找書生')`。**被打**：沿用巡怪的反擊（`fightMode` 完整、`counterAttack` 開才作用），路過格子的 `pass` 階段保留，因為被打的偵測靠那一個 tick；其餘不打。測試 `tests/integration/game/map-hunt-scholar.test.js`（假時鐘要在送出任何指令前換上，送出佇列用 `Date.now` 算間隔，所以測試先用早一小時的時鐘打開助手再撥時間）。

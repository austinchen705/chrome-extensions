# 地圖巡怪：街景模式（掃描）

- **街景模式（掃描）**：`start({ scan: true })`（面板「巡怪」列的 `.hscan`，不用勾怪）。目標是 `graph.rooms` 裡 `mapVisited`（`{ "區域/房間": { at, state: 'seen' | 'blocked' } }`，`normalizeVisited` 讀回時過濾壞資料，`deps.visited`／`deps.markVisited`，`content.js` 的 `markHuntVisited` 排成一條讀改寫佇列）沒有的房間；`inspect` 在 `scan` 時 `l` 之後只 `learnPlaces` 與標記 `seen`（空房間也記，因為 `mapMonsters` 不記沒怪的房間）就換下一間，不 finger、不打。`learnVisit` 的 `picked` 傳 `null`＝驗證這間記錄的**每一隻**怪（沒看到累計 miss，`MISS_LIMIT` 次才移除，掃一次不會直接刪）。走不到的（`走不過去`、`走錯房間`、`走不到`、試不出路）記 `blocked`，下次掃描會再試一次（只有 `seen` 不再走，所以不用清掉紀錄；`讀不到房間` 不記，可能只是慢）；`走不過去`／`走錯房間` 時把那一步加進 `state.badEdges`，`plan` 用 `dropEdges` 把它從圖拿掉，門後面的房間直接判定走不到，不會吃 `MAX_SKIPS` 也不會一間一間等逾時。掃描強制 `loopRounds: 'off'`（不送 `time`、不待命、`endRound` 直接 `finish`「掃描完成」）；`vitals` 在 `scan` 時氣低於 `dangerBelow` 就 `goHomeAndStop`（不管補氣方式）。設定頁「地圖怪物蒐集」顯示走過與走不到的間數並可清除（`mapVisited` 在 `settings-backup.js` 的資料區塊）。**掃描的路線處理**：`learn` 恆為 on（`settings.learnExits === 'on' || scan`）；`inspect` 在 `l` 回應回來時 `deps.room()` 和目標房間不同（自己手動跑掉）就丟掉這份輸出、回 `plan`（巡怪模式一樣）；走不到的房間第一輪放進 `state.deferred`（不記），`endRound` 掃描時把它們當成第二輪目標（`state.retried`，清掉 `badEdges`），第二輪才 `markScan(…, 'blocked')`；試出口（`startTrial(here, want)`）先試開頭和 `want` 相同、後面接 u／d 的出口（圖上 s → su／sd），再試開頭相同的，最後才是其他；掃描的寬鬆圖經 `withReverse` 補上單向箭頭的反方向（猜的邊，輸給嚴格圖）；`試不出路` 在掃描時不計入 `MAX_SKIPS`。終南山的真實地圖樣本（使用者貼的）顯示石階那串是單向的 ↓，反方向圖上沒有。**手動蒐集在巡怪、掃描時暫停**：`map-collect.js` 的 `setSuspended(fn)`，`content.js` 注入 `() => hunt?.on()`；`MutationObserver` 與 `flush` 兩處都先看它（暫停時看到的怪不記，也不留到之後）。原因：它等 `SETTLE_MS` 才讀 `currentRoom`，巡怪走得快時會把怪記給下一間或上一間，而它只增不減；巡怪自己的 `learnVisit` 在確認走到的房間 `l` 之後才記，是準的。測試 `the manual collector pauses…`。**打怪前補掃**（`prescan` 設定，預設 on）：`start()` 在一般巡怪時，若 `graph.rooms` 裡有 `mapVisited` 沒有的房間（`seen` 與 `blocked` 都算有圖資，不補掃）就把那些房間當目標、`state.prescan = true`（`state.scan` 也是 true，所以走街景模式的路徑：照實際出口、不打、不問人、氣到危險線回家）；此時勾選的怪的房間可以一間都沒有，不擋。`endRound`（先做完第二輪重試）看到 `prescan` 就 `startHuntAfterPrescan`：`deps.readStore()` 重讀補好的資料、`huntTargets` 重算目標（和 `start` 共用），沒有目標就 `finish` 說明；有就把 `scan/prescan/learn/targets/after/round` 換成一般巡怪（`learn` 回到設定值）。`offset`（`time` 校準）在 `start` 就讀好放進 state。測試底座的 `REQUIRED` 預設 `prescan: 'off'`，不影響舊測試。**學到的邊取代圖上同一目的地的邊**：`buildGraph` 在房間的出口已讀過（`learned.exits`）時，圖上通往某間、而那一間已有學到的邊（`learned.to`）、且圖上的指令不在出口裡的邊會拿掉（圖上往 s、實際 su），否則寬鬆圖的最短路線挑到走不通的 s，要試出口卻沒有沒試過的，每個目標都「試不出路」（使用者貼的 console：站在 l6、出口 ne／su，所有目標連續略過）。`withReverse` 補猜的反方向邊時，那間已有通往這裡的邊就不補。測試 `scan: an exit already learned…`（只剩最遠一間當目標，才會走到寬鬆路線）。**卡住偵測**：`tick` 在掃描時每次讀 `deps.room()`，房間沒換、`doneWith`／`skipTarget` 也沒更新 `state.progressAt` 超過 `SCAN_STALL_TICKS`（180 秒，用 tick 數算，測試縮小計時器時會跟著縮）就 `finish` 並警報，訊息帶 `describe().text`（階段、目標、休息百分比）；`skipTarget` 在掃描時印 `[catworld] 掃描略過` 診斷行。**還沒做**：自動一區一區換區（回家＋總路徑表 `run e 5n 2o <路線>`，目前 36 個有紀錄的區域裡 14 個完全同名、9 個只有開頭相符、13 個沒有路線；入口路線落點、地圖是否自己切區都還沒有真實遊戲的驗證）、打怪前自動補掃、「已走過 N／M 間」顯示在選怪清單。

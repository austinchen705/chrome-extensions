# 地圖巡怪：巡怪紀錄、手動紀錄、擬人化

- **巡怪紀錄**（`map-hunt.js` 的 `record`／`exportLog`，記憶體裡最多 `LOG_MAX`（2000）行，不寫儲存、不進設定備份）：目標房間、走每一步與走到哪、看房間（怪帶 `<狀態>`、勾選的標 ✓、別人只記人數**絕不記 ID**）、略過原因、開打與結果、只下 fight 每次 `assistJudge` 的判斷、休息（`restStep`：開始休息寫氣與休息線、送休息指令寫指令、回到繼續線寫「休息結束」）、每次看負重（`checkLoad`：讀不到、未超過與下次隔幾間再看、超過後去整理或停止）、停止原因。設定頁「複製巡怪紀錄」送 `HUNT_LOG` 給遊戲分頁（`content.js` 代回 `hunt.exportLog()`），前面加版本號。新增會影響「有沒有走過去、有沒有打」的分支要補一行 `record`。**每輪摘要**（`logRound`，每輪結束、這一輪處理過房間時寫進同一份紀錄（被「重生前停打」提早結束的那一輪，只要送過指令也寫），事件名「輪摘要」，不受 `humanize` 開關影響；掃描不寫）：開始時間離重生整點幾秒、路線（走到的房間序列，最多 `SUMMARY_ROOMS_MAX` 間）、指令清單（連續重複壓成「指令×次數」、`finger` 與 `give` 不帶後面的 ID 與物品、最多 `SUMMARY_TEXT_MAX` 字）、指令間隔最短／平均／最長、看了幾間有怪幾間、和上一輪路線相同或不同。**間隔用指令真正送出的時間算**：`content.js` 的 `pumpQueue` 送完巡怪的項目（單一指令，或巨集拆出來的每一步）就呼叫 `hunt.noteSent`，不是引擎決定要送的時間（排隊等指令間隔，兩者差一個間隔；巨集只決定一次但每一步都有自己的送出時間）。「開始時間離整點幾秒」用這一輪開始時最新量到的伺服器時間偏差（`beginRound` 收 `calibrate` 或等待中重新校準的結果），不是按開始時量的。摘要的組字在模組層的 `summaryLines({ startAt, sends, path, tail })`（`CatworldMapHunt.summaryLines`，`logRound` 與手動紀錄共用，第一行最後接 `tail`）。**手動紀錄**（`content.js` 的 `manualRecord`、`startManual`／`stopManual`，面板「巡怪」列的 `.hmanual`「● 記錄」，開著寫「● 記錄中」、紅底；巡怪列最多六顆按鈕，面板只有 310px，`.hunt-line .mini` 可以換行、靠右，jsdom 算不出排版，這是用真的 Chrome 截圖確認的）：開著時在 document 捕獲階段聽 `submit`，表單是 `#input` 的表單就記下輸入框的值與那一刻的時間（空白不記、聊天照記）；`sendCommand` 送出表單前設 `sendingOwn`，所以擴充功能自己送的（巡怪、觸發、定時、劇本、驗證碼答案、驗證按鈕的 `alias`）都不算。不靠輸出的回聲：遊戲的回聲有時是「> 指令」、有時是單獨一行（使用者貼的真實輸出，巨集送出的兩段也是單獨一行），和一般輸出分不開。**遊戲巨集按鍵也記**（`noteManualMacro`）：`content.js` 本來在視窗捕獲階段聽巨集按鍵（處理 `@等待` 用的，條件和遊戲一樣），沒有 `@等待` 的巨集仍交給遊戲送，只是同時把那一格用 `;` 拆開、每一段記成一個指令，時間都是按下那一刻（遊戲同步全送，樣本裡兩段的回聲也連在一起）；有 `@等待` 的巨集由擴充功能自己跑，owner 是 `PRESSED_MACRO_OWNER`（`pressed`），`pumpQueue` 送出它的每一步時記（真正送出的時間）。空白與 `<enter>` 不記（`noteManualSend` 用 `CatworldTimer.commandText`）。**遊戲的巨集是不是也透過送出表單送出沒有實測**；如果是，submit 那條會重複記一次（目前假設不是：遊戲是直接拆 `;` 送）。房間每 `MANUAL_ROOM_MS`（1 秒）與每記一個指令時看一次 `CatworldMapCollect.currentRoom`，換了才記（起點不算一步）。**分段**：開始時用巨集送一次 `time`（`askGame` 的送出方式換成 `startMacro('time', 'manual')`，閒置時佇列不送；它經過 `sendCommand`，所以不算玩家的）校準伺服器時間偏差，之後按 15 分鐘重生整點（`CatworldMapHunt.RESPAWN_MS`）分段：每記一個指令、每秒看房間、關掉時都先 `rollManual`，伺服器時間跨過這一段的整點就 `writeManualSegment` 寫出這一段（`summaryLines`，三行「手動摘要 第 N 段：…」寫到巡怪紀錄，`hunt.recordLine`，同一份、同一個 `LOG_MAX` 上限；N `tests/integration/game/map-hunt-human.test.js` 的 `manual:`（`typeIn` 填輸入框再送出表單，和遊戲收到 Enter 一樣會觸發 submit）。**真實遊戲裡按 Enter 是否觸發表單的 submit 沒有實測**（擴充功能自己送指令就是送出表單，遊戲收得到，所以應該是）。設定 `humanize`（預設關，設定頁「擬人化」摺疊）是擬人化功能共用的開關，引擎的隨機都從 `deps.random`（預設平台亂數，測試注入固定值）取。**擬人化的每輪隨機**（`humanize` 為 on 且不是掃描才作用，`humanizeRound` 在每一輪開始時呼叫：按開始、打怪前補掃完、等完重生；關著時 `state.settings` - **送出的指令也記進巡怪紀錄**（設定 `logCommands`，預設 `on`，設定頁「進階」摺疊；`map-hunt.js` 的 `noteCommand`）：巡怪進行中（`state` 不是 null，`starting` 與停止之後不記），每個真正送出的指令寫一行 `HH:MM:SS <房間> 送出 <指令>（<來源>）`，和其他紀錄行照時間排在一起。記錄點在 `content.js` 的 `pumpQueue` 送完一個項目之後（和 `noteSent` 同一處，所以時間是真正送出的時間）；來源由項目的巨集 owner（沒有巨集就用 `source`）對成中文（`SOURCE_LABELS`：`hunt` 巡怪、`hunt-home` 巡怪回家、`trigger:*` 觸發、`timer` 定時、`random` 隨機、`macro`／`user` 巨集、`manual` 手動、`chat` 聊天回覆、`script` 劇本、`emote` 表情、`alias` 別名、`shop` 商人，對不到的照原字串）。**聊天回覆、劇本、表情只寫 `送出（聊天回覆）`，不寫內容**（可能含別人的 ID 或對話）；`finger`、`give`、`tell` 只留指令名（同每輪摘要）。**巡怪的走路指令不記**（`record` 已有「走 X → 目標…」）：`map-hunt.js` 的 `sendOrStop(command, onSent, quiet)` 第三個參數 `quiet` 經 `deps.send`、`queueCommand`、`enqueue` 存成佇列項目的 `quiet`，`pumpQueue` 看到就不記；走路（`walk`、走錯路與打錯字的那一步、學出口試走與走回來）都傳 `true`，其他巡怪指令（看房間、開打、撿屍、補氣、整理…）不標用途，看緊鄰的紀錄行判斷。**手動**：玩家從輸入框送出的（`content.js` 的 submit 捕獲）與沒有 `@等待` 的遊戲巨集鍵（`noteManualMacro` 每段一個）由 `noteManualSend` 呼叫 `hunt.noteCommand(指令, '手動')`，不管手動紀錄有沒有開；有 `@等待` 的巨集鍵（owner `pressed`）在 `pumpQueue` 只走 `noteManualSend`，不會被佇列的通用記錄再記一次。每輪摘要的「指令 N 個」不受影響。測試 `tests/integration/game/map-hunt-human.test.js` 的 `command log:`、`tests/integration/settings/map-hunt-settings-ui.test.js` 的 command log switch。

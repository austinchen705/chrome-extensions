# 資料檔

## shop-items.tsv

商人賣的裝備資料，252 件（2026-11-04），Tab 分隔，第一列是標題。由設定頁「裝備資料庫（商人 check）」的「複製」匯出，是作者在商人面前自己打 `check 編號` 蒐集的結果。

| 欄位 | 說明 |
|---|---|
| 名稱 | 商品名稱，和 list 裡一樣（`[大日皇鞭]` 的方括號是遊戲顯示的） |
| 類別 | 例如 `刀類武器`、`手套類防具` |
| 主要數值 | 傷害力（武器）或防禦力（防具）；check 輸出沒有時留空（衣物類、暗器類、部分盔甲） |
| 佩帶經驗 | 佩帶條件的經驗，沒有條件填 0 |
| 屬性 | 附加屬性，用空白分隔；沒有就留空 |

**同名裝備的主要數值與屬性不一定相同**，所以這份資料可靠的是「類別」和「佩帶經驗」；傷害與屬性只是蒐集當下那一次 check 到的值，不要當成標準值。

這份資料已經內建進 extension（`catworld-auto-command/shop-data.js`，由 `node tools/gen-shop-data.js` 產生），更新 extension 就會用到；改了這個檔要重新產生並升版本。

## map-monsters.tsv

地圖視窗蒐集到的怪物位置，349 個房間、36 個區域（2026-11-03），Tab 分隔，第一列是標題。由設定頁「地圖怪物蒐集」的「複製」匯出，是作者自己走過各房間時蒐集的結果。

| 欄位 | 說明 |
|---|---|
| 區域代號 | 地圖視窗的區域代號，例如 `wudon`（對應地圖房間 `m-區域-房間` 的區域） |
| 區域名稱 | 地圖標題上的區域名稱，例如 `武當派` |
| 房間代號 | 地圖房間代號，例如 `2c` |
| 怪物 | 該房間出現過的怪物，`名稱(ID)`，用逗號分隔 |

- 只收帶括號 ID 的怪物；別的玩家的英文 ID（舊版誤記的）已經濾掉。
- 紀錄只增不減：房間裡的怪會移動，所以只代表「曾經在這間看過」，不保證現在還在。
- 只涵蓋作者走過的區域，不是完整清單。
- 這份資料已經內建進 extension（`catworld-auto-command/map-data.js`，由 `node tools/gen-map-data.js` 產生），更新 extension 就會用到；改了這個檔要重新產生並升版本。

內建的 3 份備援劇本不含時事，直接寫在 `catworld-auto-command/chat-script-data.js`。`tests/chat-script-content.test.js` 檢查這 12 份與內建劇本：通過驗證規則、7～8 輪、題材分佈、來源註明、不碰禁區字眼、開場句彼此分得開。

- 時事 6 份（娛樂 2、遊戲 4）：「週」是 `2026-11-09`（從那天起 14 天內才會用），第一列「備註」寫了來源與日期。來源是三立新聞網 2026-09-16 的金馬影展報導（影展 11/6～11/22）與 Famitsu 2026-11-06 的 11 月 Switch 新作表；遊戲那四份的事件在 11/5～11/12（Minecraft Dungeons II 11/10，其餘 11/12），11/12 之後請從試算表拿掉。

## chat-scripts-evergreen.csv

劇本對話的常青劇本，4 份（手搖飲選擇困難、追劇停不下來、手機相簿太多、新買的小盆栽），不含時事，「週」欄留空＝永遠可用，所以不用每週換；每份 14 個來回（28 輪，一份最多 30 句）。欄位和 `docs/templates/shared-chat.csv` 一樣。設定頁「劇本試算表連結」的預設連結（`shared-data.js` 的 `DEFAULT_SOURCES.chat`）指向的就是把這份放進去的試算表分頁，這個檔是它的備份。

**匯入試算表時，匯入位置選「插入新工作表」，不要選「取代試算表」或「取代目前的工作表」**：取代會把整份試算表（或那個分頁）蓋掉，同一份試算表裡別的分頁（例如驗證碼樣本收集的「樣本」）也會不見。匯入後把新分頁改名「劇本」，對這個分頁「發布到網路」（CSV），拿到的連結 `gid=` 和原本的不一樣，要換到設定頁與 `DEFAULT_SOURCES.chat`。

這份檔不在自動測試裡；新增劇本時用 `buildChatScripts` 檢查（通過驗證規則、沒有被丟掉的列），開場句要和其他所有劇本（含內建、第 45 週那批）的相似度低於 0.8，B 才認得出是哪一份。

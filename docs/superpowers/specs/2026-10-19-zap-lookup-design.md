# zap 攻略資料查詢（catworld-auto-command）設計

## 目的與原因

玩家在遊戲（`https://catworld.muds.tw/web*`）裡遇到怪物、無名物品或謎題時，得切到攻略站 `https://zap.muds.me/` 查資料，來回切換很煩。目標是把攻略站的資料整理進 extension，直接在遊戲頁查詢，不必離開遊戲。

三個查詢需求（依實作順序）：

1. **打怪**：讀目前經驗，列出適合打的怪；遊戲中出現怪物名時顯示該怪資訊。
2. **無名物品**：顯示物品等級，並建議「做武器」或「賣掉」。
3. **解謎**：在工具內搜尋謎、看步驟，路徑指令可一鍵送出。

## 目標 / 非目標 / 反目標

目標
- 資料離線可用，查詢不需要離開遊戲頁。
- 三個查詢共用同一套「抓站、產生資料檔」的工具。

非目標
- 不做即時爬站；資料是產生的靜態檔，站方更新時重新產生。
- 不做地圖圖片或座標：zap 站與 help 站都沒有圖，「位置」只有文字。
- 不自動戰鬥、不自動決定要打哪隻怪。

反目標
- 即使功能正常，只要分級顏色誤導玩家去送死（把危險怪標成綠色）就算失敗；所以分級門檻要可調、預設要偏保守。

## 資料來源（已查證）

| 資料 | 來源 | 結構 |
|---|---|---|
| MOB 列表 | `https://zap.muds.me/ot1.htm` | 一張約 840 列的表：名稱(ID)、經驗值、位置、備註。位置是文字，無座標 |
| 無名物品 | `https://zap.muds.me/ub.htm` | 依 LV1～LV5 分級的物品名稱格子，另有鑑定方式說明文字 |
| 解謎 | `https://zap.muds.me/qu*.htm`（約 40 頁，目錄在 `list.html`） | 每謎一頁，步驟文字，內含 `run ...` 路徑指令 |
| 遊戲說明 | `https://catworld.muds.tw/help/*` | 地圖（`maps`、`map.N`）只有各州的文字路徑 |
| 新手怪列表 | `https://catworld.muds.tw/help/newstart.3` | 約 86 列純文字：「完整名稱(ID) 數值 備註」。無位置欄；部分數值是範圍（如 `75000~80000`、`土匪 3000~~~~6000`） |

頁面編碼是 UTF-8；`ot1.htm` 約 350KB。

## 已決定的規則

- **讀經驗**：從遊戲頁 `#exp`（`#monitor` 內）讀目前經驗，例如 `414748`。
- **有沒有潛能**：MOB 表的「經驗值」欄是怪物本身的強度數字 `S`（不是打一次拿到的經驗）。令 `E` 為目前經驗（`#exp`），`q = S × 2 / E`；`q > 1`（即 `S×2 > E`）打了才有經驗／潛能，`q ≤ 1` 沒有。`q` 越大越難打。
- **顏色分級**（官方沒有公開門檻，是玩家依遊戲體驗猜測；遊戲本身會替 mob 上色，此處要與之一致）：
  - 白：`q ≤ 1`，打了沒有潛能（遊戲裡實際顏色是灰 `#555555`，面板用同色呈現）
  - 綠：`q > 1`，有潛能且安全
  - 黃：要小心
  - 紅：`q` 太大，打不過
- **校準點**（使用者實測，`E = 414748`）：忽必烈（`S = 250000`，`q≈1.21`）＝綠；猛虎大將軍 蒙古將軍（`S = 500000`，`q≈2.41`）＝黃；大臣＝白（遊戲顯示 `#555555`，但 MOB 表查無此怪，沒有數值）。所以綠區間涵蓋 `q≈1.21`，黃區間涵蓋 `q≈2.41`，白的上界是 `q = 1`（使用者規則）；綠／黃的切分點在 1.21～2.41 之間、紅的起點在 2.41 以上，尚無校準點。
- 切分點放在設定裡可調；預設值依校準點由建構者先猜（偏保守，寧可把危險的怪標成黃或紅），之後使用者再對照遊戲顏色補校準點。
- **路徑補前綴**：單純的一次性移動路徑（例如商店、地圖頁的獨立路徑），若不是以 `run e 5n` 開頭，自動補上 `run e 5n 2o`（醉仙樓出發，統一格式）。已是 `run e 5n 2o` 或 `run e 5n o` 開頭者不動。**解謎的步驟內路徑一律保持原樣不補**（可能是接在上一步位置後面走）。
- **localStorage／storage**：資料檔當作內建；`chrome.storage.local` 只存使用者設定（分級門檻）與個人標記（例如已解的謎）。
- 風格沿用現有做法：資料檔仿 `skills-data.js`，由 `tools/` 下的腳本產生、不手改。

## 同名怪比對

MOB 表有 841 列，只有 647 個不同的英文 ID；55 個 ID 重複出現（共 249 列），其中 49 組的強度數字不一樣（例如 `guard` 共 37 列，數值從 35000 到 70000）。所以**不能只用 ID 比對**。

- 比對鍵是**完整顯示名稱**（含門派／稱號前綴，例如「護衛團 蒙古兵(Guard)」），不分大小寫。
- 完整名稱命中唯一一列：顯示該列的強度、顏色、位置、備註。
- 只命中到 ID、有多列：**不猜**，列出所有候選（各自的強度、顏色、位置），讓使用者自己對照所在地點。
- 遊戲輸出的房間名（例如「迴廊」）只是單一房間，不是表上「位置」欄那種區域名（如「全真」「襄陽」），兩者對不上，**不用房間名篩選**；位置只顯示給使用者看。
- 位置欄是文字，可能有多個地點（如「蒙古、襄陽」），顯示時照原文。
- **兩個來源合併**：zap 的 MOB 表最小數值是 10000，沒有新手怪；`newstart.3` 補低階怪（實例：「第四代全真弟子(Alltruth taoist)」數值 2000，只在這裡）。86 列中 37 列與 zap 重複，49 列只在 newstart。合併規則：
  - 以「完整名稱(ID)」比對，**不分大小寫**（`Alltruth` 與 `alltruth` 視為同一隻）。
  - 兩邊都有：優先用 zap（有位置、備註）；兩邊數值不同（重複的 37 列中有 9 列不同，如老虎 105000 vs 500）時，記錄兩個數值並以較大者分級（保守），產生腳本印出差異列表供人工確認。
  - 數值是範圍時，記 `min`、`max`，分級用 `max`（保守）。
  - 只在 newstart 的怪沒有位置，顯示備註即可；位置由使用者手動補（見下）。
- **手動補充檔**：`tools/zap-overrides.json`（使用者維護、進版控），是一個陣列，每項 `{ name, location?, exp?, note? }`，`name` 是「完整名稱(ID)」（不分大小寫）。產生腳本最後套用它，**補充檔的值優先於兩個網站**：
  - 有 `location`：以「名稱＋位置」為鍵——對得上既有那一隻就覆蓋，對不上就**新增一隻**（同名不同地點的怪，如桃花島與長安城的老虎）。
  - 沒有 `location`：只對「該名稱只有一隻」的怪覆蓋；名稱有多隻時視為錯誤並列出。
  - 補充檔裡的 `name` 兩個來源都沒有，也視為新增的怪。
  - 產生時印出「補充檔項目找不到對應怪或有歧義」的清單，防止打錯字。
- 兩個來源都查無的怪，浮層顯示「表上無此怪」，不給顏色。

遊戲輸出的怪物行格式（使用者實際貼的樣本）：

```
迴廊 -
    你正站在迴廊轉角的地方，迴廊從這往東及北邊而去。
    這裡明顯的出口是 north 和 east。
  ※第四代全真弟子(alltruth taoist) [fight][kill]
  ※第四代全真弟子(alltruth taoist) [fight][kill]
```

- 怪物行以 `※` 開頭，後面是「完整名稱(ID)」，行尾有 `[fight][kill]` 等按鈕標籤；比對前要去掉 `※` 與標籤。
- 同一房間同一隻怪可能出現多行，提示時合併成一筆並顯示數量。

## 階段

1. 打怪（含產生工具與資料檔、面板、怪物出現時的資訊提示、可調門檻）
2. 無名物品
3. 解謎

每階段可單獨使用、單獨發版。下面的細節以第 1 階段為主，2、3 階段開工時再補。

## 留給建構者決定

- 面板放在遊戲頁何處、如何呼出，與現有面板的關係（先讀 `content.js`、`popup.html`）。
- 怪物名稱比對的細節（見下方「同名怪比對」的規則）。
- 資料檔格式與產生腳本的位置（建議 `tools/gen-zap-data.js`，輸出 `catworld-auto-command/zap-data.js`）。
- 分級預設門檻的數值。
- 依專案 `CLAUDE.md`：升 `manifest.json` 版本、`CHANGELOG.md` 加一筆、README 補操作說明。

## 設計者先做的決定（可推翻）

- **怪物出現提示**：只處理 `#content` 新增的文字，沿用「只看新文字、略過浮動視窗、不重複提示同一隻」的原則；提示是遊戲頁上的小浮層，數秒後自動消失，不會每次重畫房間描述都跳。
- **適合的怪列表**：預設列出「綠色區間」，依強度數字由高到低排序，每列顯示名稱、強度數字、位置、備註；有搜尋框可依名稱或位置過濾，並可切換顯示黃色區間。
- **資料載入**：`zap-data.js` 只在使用者開啟查詢面板時才載入（`chrome.runtime.getURL` 取得），不隨每個遊戲分頁的 content script 載入；manifest 與 popup 的備援注入照現有 `skills-data.js` 的做法處理。
- **異常列**：經驗值缺漏或非純數字的 MOB 列，產生腳本不丟棄，改為標記「經驗未知」並在產生時印出列表，列表中以灰色顯示、不給分級顏色。
- **測試資料**：在 repo 內存一份縮減過的 `ot1.htm`、`ub.htm`、謎頁樣本作為產生腳本的測試輸入，測試不連網。

## 已知限制

- 「找地圖」只能顯示位置文字與路徑，沒有圖。
- 站方內容更新後需要重新產生資料檔。
- 無名物品 LV5 是 2017 新年限定（站上註記），不一定拿得到。

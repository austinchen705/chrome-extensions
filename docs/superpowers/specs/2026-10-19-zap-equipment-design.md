# 無名裝備鑑定比較（zap 第 3 階段）設計

上層設計：`docs/superpowers/specs/2026-10-19-zap-lookup-design.md`。第 1、2、4 階段已完成。第 3 階段原本因為使用者說「不用比較」而取消，後來使用者更正：**鑑定出來的裝備若比現在穿的好，要標出來**，所以重新開做。

## 目的與原因

在長安鑑定屋找馬鑑定師鑑定一批無名裝備後，使用者要逐件判斷「這件比我現在穿的好嗎、要不要留」。目標：鑑定完，面板直接標出每件相對於「你現在穿的同部位那件」是比較好、比較差、相當，或沒有基準可比，並說明原因。

## 目標 / 非目標 / 反目標

目標
- 解析鑑定輸出的「此物名曰」區塊，與已存的「目前穿著」基準比較，面板浮層標出結果與理由。
- 面板提供「讀取目前穿著」，一次取得身上每件裝備的數值並存起來；之後被動更新。

非目標
- 不自動穿脫裝備、不賣、不丟；不跨部位比較（披風只和披風比）。
- 每次鑑定時**不送任何指令**；只有使用者按「讀取目前穿著」時才送指令（唯讀的 `i` 與 `view`）。
- 不處理雜物（那是第 2 階段，另一條路：衰老頭）。

反目標
- 把比較差的裝備標成「比較好」。判斷不確定時（沒有基準、格式讀不懂）一律回「無法比較」，不猜。
- 用過期的基準而不告知使用者。

## 資料來源（已用真實遊戲輸出查證）

**鑑定輸出**（找馬鑑定師，下 `identify`）：開頭 `> 你想請馬鑑定師鑑定所有無名物。`，每件裝備一個區塊，結尾 `馬鑑定師說道：共鑑定N樣無名物…`。

```
此物名曰 ：鋼盔甲，盔甲類防具
品    階 ：下乘之品            （有的沒有）
硬    度 ：76
防 禦 力 ：37 / 37             （武器是「傷 害 力 ：48 / 48」）
屬    性 ：+2   行動           （可有多行，數值可為負，如 -8   重量）
潛    能 ：+7 ，損修 0 / 82    （有的有）
佩帶條件 ：經驗 60000          （有的前面還有「使用者 xxx，」）
```
- 區塊之間會夾雜：`特殊物品非無名裝備, 無法幫你鑑定。` 與一整塊文字圖案（`╔▆▆▆…`），要略過。
- 標題的類別是「○○類防具」或「○○類武器」。已見過：披風、盔甲、手套、項鍊、戒指類防具；拳套、杖、刀類武器；zap 還列有頭盔、腰帶、鞋子、盾牌、衣物、劍、鞭、暗器類。
- 名稱可能被 `<span>` 拆開上色；欄位標籤中間有空白（`防 禦 力`、`傷 害 力`），解析要容忍。

**目前穿著**：`view` 一件穿著的裝備，輸出和鑑定的「此物名曰」區塊**格式相同**（使用者貼過暮歌、黑羽長風鎧）。`i`（背包）輸出中穿著的行有 `ˇ` 標記，HTML 是：

```
<span class="H3"> *</span><span class="H6">ˇ</span>…名稱…(id) [<a target="view #1791388801582056">view</a>][<a target="remove #…">remove</a>]
```
武器是 `[unwield]`。`view #編號` 就是可以送出的指令。

## 比較規則

使用者定的規則：**先比攻擊力／防禦力，再比附加屬性；和自己主要武器類型相關的屬性加分**（例：劍術 +1、攻擊 +1 都算分）。

- 基準與候選要**同類別**才比（標題的類別相同，例如都是「披風類防具」；武器要都是同一類武器，用劍的人，銅棒不和紫皇劍比）；沒有同類別的基準 → 「沒有基準可比」。
- 主要數值：武器取傷害力、防具取防禦力（`/` 前面的數字，實際值）。
- 判斷順序（設計者的猜測，數值可調）：
  1. 主要數值相差 **3 以上** → 數值高的較好。
  2. 相差 2 以內視為相當，再比**附加屬性分數**：相關屬性每點 2 分、其他正向屬性每點 1 分，負值的屬性照負數扣分；分數較高者較好，相同則「相當」。
  - 「重量」「硬度」「潛能／損修」不計分（只顯示）；`-8 重量` 是變輕，不是壞事。
- **相關屬性**：`攻擊`（所有人）加上主要武器類型對應的技能名：劍→`劍術`／`劍法`、刀→`刀術`／`刀法`、杖→`棒法`／`杖法`、鞭→`鞭法`、拳套→`拳腳`、暗器→`暗器`／`暗器使用`。主要武器類型沿用第 2 階段的設定（`chrome.storage.local.mainWeapon`）；未設定時只有 `攻擊` 算相關。
- **穿戴條件**：需求經驗大於使用者目前經驗（`#exp`）時，加註「你還不能穿」（仍顯示比較結果）。
- 結果文字：「比現在好，建議留下」「比現在差」「相當」「沒有基準可比」，後面接理由（例如「防禦 +6、多了 攻擊 +5」）。

## 基準：讀取目前穿著，之後被動更新

- 面板新增一列「裝備」，按鈕「讀取目前穿著」。按下後：
  1. 送 `i`；從新增的輸出裡找出**有 `ˇ` 標記的行**的 `view #編號`（背包的穿著清單，約 11 件）。
  2. 把這些 `view #編號` 以一個巨集送出（走 `startMacro`：共用佇列、間隔、驗證碼取消、面板「巨集」列可停止；與解謎「送出」同一條路）。
  3. 每個回來的「此物名曰」區塊解析後存成基準。
  - 等不到 `i` 的輸出（逾時 10 秒）時顯示「沒有讀到背包」，不送任何 `view`。
- 基準存在 `chrome.storage.local.wornEquipment`：`{ [類別]: [ { name, primary, attrs: [{ name, value }], needExp, readAt } ] }`，每個類別是一份**清單**（同類別可能穿兩件，例如兩枚戒指），以名稱區分、每件各自記 `readAt`。
- **被動更新**：不在鑑定過程中、出現的「此物名曰」區塊，若名稱是目前穿著的（來自最近一次 `i` 的穿著名單）就更新該類別的基準；使用者自己 `view` 穿著的裝備也會更新。
- 每行比較結果旁註明「基準讀取於 N 分鐘前」，過期（使用者可能換過裝）時請再按「讀取目前穿著」。
- 每次鑑定都**不送指令**；一次「讀取目前穿著」約 12 個指令（1 個 `i` ＋ 約 11 個 `view`）。

## 顯示

- 共用面板底部浮層，新增「鑑定裝備」區段（與怪物提示、雜物鑑定結果共用同一個計時；與第 2 階段一樣，連續鑑定時結果累積、最多留最新 N 件，N 由建構者決定，建議 12）。
- 每件一行：名稱（類別）、主要數值、屬性摘要、需求經驗、比較結果與理由；「比現在好」用綠色、「比現在差」用灰、「相當」用黃、「沒有基準可比」用淡色。
- 「裝備」列顯示基準狀態（例如「已讀取 11 件，3 分鐘前」或「尚未讀取」）。
- 鑑定過程邊界：`> 你想請…鑑定所有無名物。` 開始、`共鑑定N樣無名物` 結束；兩者之間的區塊才當候選；在兩者之外出現的區塊只用來更新基準。

## 設計者先做的決定（可推翻）

- **同類別有多件（兩枚戒指等）**：候選與該類別**最弱的那一件**比，說明裡寫出比的是哪一件（「比你的『骷髏戒指』好」）；比最弱的那件還差就不可能比任何一件好。這樣不會把比較差的裝備標成比較好。
- **類別用標題原字串**（「披風類防具」「盔甲類防具」…），不另做部位對照表；沒有同類別的基準就是「沒有基準可比」，並提示「還沒有這個類別的基準，先按『讀取目前穿著』」。武器只在同一種武器類別內比；`mainWeapon` 只影響屬性加分，不影響要不要比。
- **屬性名稱**：先做字元正規化（`補助`→`輔助`、`回復`→`恢復`），已知名稱查一張別名表（相關屬性別名見上）；表上沒有的屬性，正值每點 +1 分、負值每點 −1 分；`重量`、`硬度`、`潛能／損修` 不計分。
- **穿著的辨識**：`i` 輸出的穿著行（有 `ˇ` 標記）由觀察器拿到**新增的 DOM 節點**，依節點順序掃描：行內出現 `ˇ` 後，同一行（遇到換行重置）的 `a[target^="view #"]` 就是穿著裝備的 `view` 指令；同時記下穿著的名稱。`view` 的回應區塊不含編號，與送出的 `view #編號` 以**順序**配對，並以名稱檢查。
- **被動更新**只在「名稱是穿著名單裡、而且穿著名單裡沒有同名的第二件」時才做；有同名時只有按鈕讀取會更新。被動更新只重設那一件的 `readAt`，不動同類別其他件。
- **鑑定進行中**：從 `> 你想請…鑑定所有無名物。` 到 `共鑑定N樣無名物` 之間算一次鑑定；這期間「讀取目前穿著」按鈕停用；結尾句一直沒來時，30 秒內沒有新區塊就自動結束這次鑑定。

## 留給建構者決定

- 「此物名曰」區塊的解析（欄位標籤容忍空白、有／無品階、潛能行、多行屬性、被 `<span>` 拆開的名稱、插在中間的文字圖案與「特殊物品非無名裝備…」）。
- 區塊跨多個封包／多批新增文字時的組合方式（沿用第 1、2 階段「新增節點文字直接相接」的做法）。
- 穿著名單的取得與「讀取目前穿著」的狀態機（等待 `i` 輸出、逾時、進度顯示）。
- 屬性名稱的正規化（`補助精回復`／`輔助精恢復`等寫法不一致）；相關屬性對照表的別名。
- 比較分數、相當的門檻（3）是設計者的猜測，要放在一個容易調整的常數，之後依使用者實際使用校準。
- 測試 fixture：存使用者貼的那批鑑定輸出（含圖案與「特殊物品」行）和 `view` 區塊樣本，測試不連網。
- 依專案 `CLAUDE.md`：新模組同步加進 manifest 與 popup 備援注入（在 `zap-panel.js`／`zap-riddle-ui.js`／`content.js` 之前）；升版本、`CHANGELOG.md`、README、`CLAUDE.md` 現況。

## 已知限制

- 比較規則與分數是猜測，使用者對照實際感受後可能要調整。
- 每次換裝後要自己再按「讀取目前穿著」（或自己 `view`），否則比較用的是舊基準；文件已要求顯示基準時間。
- 其他類別（頭盔、腰帶、鞋子、盾牌、衣物、護腕、劍類武器、鞭類武器、暗器）的實際輸出格式沒有樣本，解析會寫得寬鬆，遇到讀不懂的區塊要原樣顯示、不給比較結果。

# 產劇本對話

產出 `docs/data/chat-scripts-<批次>.csv`，用 `node tools/check-chat-scripts.js` 檢查，改到全部通過才交。劇本的格式、驗證規則、比對方式寫在專案 `CLAUDE.md` 的「劇本對話」一節，這裡只寫產的流程。

## 1. 讀參數

- `時事 N`：依本週新聞寫 N 份，「週」填本週的星期一（`YYYY-MM-DD`，本機日期），14 天內才會被採用。
- `常青 N`：不含時事、不綁日期，「週」留空。
- `主題 X`：常青劇本都圍繞 X（例：棒壘球那批）。
- `輪 N` 或 `輪 N-M`：每份幾輪，預設 8（檢查器預設接受 7～8）。一份最多 30 句。
- 沒給參數就問使用者要幾份時事、幾份常青。

## 2. 先看現有的

- 讀 `docs/data/README.md` 與一兩份現有的 CSV（`docs/data/chat-scripts-w46.csv`、`chat-scripts-baseball.csv`），照它們的語氣與長度寫。
- 把現有所有劇本的開場句與題材列出來，新的題材不要重複（檢查器只擋開場句太像，題材重複要自己避開）。

## 3. 時事：查新聞

- 用 WebSearch 查最近一週台灣看得到的新聞，題材限：科技、體育、娛樂（電影、影展、演唱會、劇）、美食、遊戲（新作、更新、賽事）、天氣（只寫溫度、季節，不寫颱風與災害）。
- **不碰**政治、選舉、戰爭、傷亡、災難、事故、犯罪、社會爭議、特定真實人物的私事。
- 每份時事劇本要有一則具體的來源（網址與日期），事件要在「週」起 14 天內仍成立；事件已經過去或會在兩週內過期的，在交付時寫明哪天之後要從試算表拿掉。
- 台詞裡的事實只寫來源裡有的；不確定的寫成角色的感想或疑問，不要編數字。

## 4. 寫 CSV

- 檔名：時事用 ISO 週數 `chat-scripts-w<週數>.csv`（2026-11-02 那週是 w45）；已存在就問使用者要覆蓋還是另取名。純常青的批次用主題名（`chat-scripts-<英文主題>.csv`）。
- 標題列 `劇本ID,順序,誰,台詞,備註,週`，UTF-8、LF、沒有 BOM；含逗號或引號的欄位照 CSV 規則加雙引號。
- 劇本ID：`<批次>-<題材>-<n>`（時事題材用 `tech` `sports` `ent` `food` `game` `weather`，常青用 `eg`），和現有的不能重複。
- 順序從 1 連續遞增；A 先說；A、B 交替（連續同一人的列算同一輪，盡量不要這樣寫）。
- 時事劇本第一列的「備註」寫：來源名稱 日期「標題」（網址）：一兩句重點。其他列備註留空，週只填第一列也可以（照現有檔案每列都填週也行，要一致）。
- 台詞風格：
  - 像兩個熟人在遊戲裡私聊：口語、短、可以不加標點，用空白代替逗號；同一輪要分好幾則送就用全形 `／` 分開。
  - 每則最多 40 字，多數在 8～20 字。
  - 不要每輪都用問句結尾（檢查器擋超過一半）；B 也要主動說自己的事，不要只附和。
  - 不寫「這週」「下禮拜」這類相對時間，要寫就寫日期或「這陣子」。
  - 不寫 `;`、`；`、`@等待`、換行；可以用 `{對方}`（送出時換成對方角色名），但一份最多一次。
  - 開場句要一看就知道在聊什麼、彼此不像（B 靠開場句認出是哪份劇本）。

## 5. 檢查

```
node tools/check-chat-scripts.js docs/data/<檔名>.csv            # 預設 7～8 輪
node tools/check-chat-scripts.js docs/data/<檔名>.csv --turns 8
```

有問題就改那幾份再跑，直到印出 `OK`。不要為了過檢查改檢查器。

## 6. 文件與交付

- 在 `docs/data/README.md` 加一節 `## <檔名>`，照現有各節的寫法：幾份、每份幾輪、時事的來源與日期、哪天之後要拿掉、常青的題材清單、貼進試算表的方式（同常青那節：匯入位置選「插入新工作表」）。
- 不改擴充功能的檔案，所以不升版本、不寫 CHANGELOG。
- commit 前先問使用者；push 一定要先問。
- 回報給使用者（繁體中文）：檔案路徑、份數、每份的題材一行、時事的過期日、檢查器的結果。
